# 主动工作、成本、旁聊与遗忘默认方案 v1

2026-10-10。D21记忆规则已确认；下列具体数值为可调默认值，尚非用户明确批准的固定偏好，不按社区夜间周期机械复制。当前实现边界见文末状态记录。

## 主动工作与成本

2026-10-10实现边界：目标提醒仍是用户主动设置的一次性本机通知；另新增可手动启动或选择开启的近期对话回顾，细节见下文。两者均不能代表自动目标跟进、周期动态、完整预算调度或可靠锁屏后台执行。

| 工作 | 默认频率/条件 | 通知 |
|---|---|---|
| 会话记忆 | 重要明确事实随回合持久化；普通闲聊不每句造记忆 | 日常更新不逐条打扰，变化列表可查看；SOUL每次改动告知 |
| 目标跟进 | 每目标24小时最多一次检查；无变化不产生催促；约定时间优先 | 每日主动通知合计最多2条，具体约定提醒/当前任务完成另计 |
| 兴趣动态 | 每日最多3条新内容，来源可靠且去重 | 默认只进动态，不逐条推送 |
| 点子 | 每日最多2个，已有未处理项优先复用 | 默认只进点子，有重要可行动变化再提醒 |
| Dreaming | 有新增交流/纠正时，每日最多一次；空输入跳过 | 默认安静；人格改动必须告知 |

Asia/Shanghai默认安静时段22:00–08:00（可改）；合并非紧急通知，保留应用内结果。计划漏跑只补最近一轮，过期新闻不重推；目标提醒改为询问是否仍相关。手机执行依系统机会，Mac连接时优先承接；无设备运行不会伪造维护成功。暂停某目标同时暂停相关跟进；全局暂停立即阻止新的主动回合。

成本以供应商实际usage及配置价格估算，不猜价格。设置前先选供应商/模型并测试一次（用户主动）；主动模型调用需启用预算。HEARTBEAT.md 当前提供每日请求/Token额度和单次最大输出设置；每日回顾每周期最多成功一次、最多两次尝试。价格表和日/月货币上限尚未实现，所以目前只提供请求额度保护，不显示金额或承诺金额硬上限。

每次回顾请求前按提示内容的UTF-8长度保守估算输入Token，并预留最大输出Token；达到请求数或Token上限时不发送模型请求。收到usage后以实际值结算；失败或无法取得usage时保留预留额度，避免重复消耗不可见。此估算不是供应商分词器计费值；两端没有原子额度分配或全局执行锁，失联时各自的本机预算不保证全局上限。不因模型错误自动无限重试。用户主动聊天目前不会被该主动维护预算拦截。

低电量模式/系统热状态异常时暂停非用户发起维护；已开始工作保存进度。耗电比较作为可运行版本后的优化项，不作开工前门槛；后台能否执行的真实性仍必须验证。

## 旁聊与记忆

一个身份、共享已确认事实/目标/构件；旁聊只带主题摘要、关联对象与必要检索，不复制全部其他旁聊。任务临时约束只用于该目标；未确认推断不进入全局。引用保留来源且不视作用户陈述。用户可选择某条内容不用于长期记忆；不把此选项误称供应商不接收内容。

2026-10-10实现切片：旁聊最多带入所选父对话最近四条已完成消息，每条限制600字；不带父消息附件、失败消息、导入历史或其他旁聊。检索父对话目标时，多个活动目标只带入与当前问题匹配的目标；若只有一个活动目标可带入该目标。该界面仍不提供逐条手选上下文。

敏感健康/财务/心理等信息默认不自动持久化为精选记忆，明确要求记住或预览选择后才提交；当前使用本地关键词规则作为保护层，涵盖常见中英文类别，不是完整隐私识别。被识别为敏感的信息会从自动回顾输入、候选提案和动态个性化中排除；用户明确保存的敏感记忆带标记，只有与当前请求关键词相符时才进入模型上下文。普通聊天仍会按所选模型配置发送给模型供应商，退出记忆或旁聊上下文不能撤回供应商已收到的数据。原聊天是否保存单独显示。外部提取统一预览；连人带事实必须确认主体。SOUL语气/习惯演化记录差异与原因，每次应用后应用内告知，安静时段不强推；核心目的与权限变化等用户明确决定。

## 纠正、撤销与忘记

纠正新增修订并重建当前视图/索引，历史仍可解释；撤销不抹除后续用户修改。忘记前展示范围：事实、相关原材料片段、日记/dreaming、构件及旧修订，用户可只停止使用或彻底删除。默认“忘记这件事”走彻底遗忘预览，避免一句话误删整封无关邮件。

本地先停检索与新提交，再清相关数据；保留仅含opaque ID/来源ID的抑制标记，无原文。离线设备显示待删除，重连先传播删除，再合并普通变更；旧任务候选不可复活。旧来源重新扫描受抑制；用户明确重新导入后才可解除。模型供应商已收到的内容不能本地撤回。

备份策略（2026-10-12，取代早期“仅迁移时生成受控加密快照”的建议）：持续使用期间，重要工作区资料应能随时备份和导出；用户选择明文 ZIP，便于在授权后交给其他 AI 阅读。手动导出独立保留，不受自动轮换影响；定时备份默认保留最近7份，可调1–30份，轮换只删除 OpenMuse 定时备份。备份包含的个人资料由用户决定是否分享。彻底遗忘无法清理用户已导出副本，界面和[备份说明](BACKUP_RESTORE.md)必须提示用户自行管理；离线旧设备和旧包导入仍需核对删除标记，独立从旧包重建可能不知道原设备后来发生的遗忘。

以上默认方案分别验收频率上限、安静时段、预算预留/失联额度、暂停立即生效、旁聊隔离、范围删除、旧包恢复和敏感内容确认。

## Mac 本机资料授权边界

用户可在 Mac 设置中主动选择一个目录供本机 Pi 只读。每轮执行先把目录中符合类型和大小限制的 UTF-8 文本复制到临时快照；Pi 只收到快照，不取得原目录写入权、shell、浏览器、网络或其他路径访问。撤销授权后，后续回合不再创建快照；正在运行的回合可由用户停止，临时快照在该回合退出后清理。活动记录与检查点只保存工具名、状态和不含正文的摘要，不保存文件内容；设置页的本机审计记录可由用户清除。文件名和相对路径可能属于个人资料，不能放入公开日志或示例。

## iPhone 对话工作区逐次写入

模型只能请求写入当前对话隔离工作区中的文本文件，单次提案最多 8 KB。Swift 宿主先检查相对路径、文件类型、大小、目录配额、符号链接和目标现状；预检不创建文件或目录。批准页显示确切路径、创建/替换状态和完整新正文。替换已有文件时显示旧文件大小，并记录旧文件摘要用于防止用户检查后目标被替换；不得把单次批准扩展成后续写入授权。

只有用户批准该条请求后才写入。拒绝会把结果回传给模型但不更改文件；取消当前任务或 App 重启会废弃尚未处理的请求，不在后台或重启后自动执行。批准后再次核对目标指纹；目标变化时中止并要求模型重新提出。活动/检查点记录状态和相对文件名，不记录正文。该工具不允许写 SOUL.md、USER.md、GLOBAL.md、MEMORY.md、HEARTBEAT.md、正式资源库、共享工作区或同步记录；手机工作区内容仍是本地临时材料。

## 手机只读网页与 iSH 命令审批（T54 当时实现边界）

**手机本机只读网页搜索/读取默认免逐次审批。** 仅当用户问实时信息、明确要求联网，或提供了要打开的公开网页时，才向模型提供对应工具；明确要求离线时不开放。只发送回答当前问题所需的公开关键词给搜索服务，不把记忆、私人消息或本地文件拼入搜索词。页面正文作为不可信外部资料，只能读取公开 HTTPS 页面；不登录、不填表、不点击提交、不修改网页。搜索词会离开手机并发给搜索服务，因此设置与隐私说明必须说清这一点。搜索失败时如实说明，不切换到 iSH 伪装浏览器。

T54 发布时的 iSH 首次命令审批卡与本对话授权，是当时实际版本，不是 D37 之后的目标策略。该历史边界保留供追溯。

**D39–D41 当前浏览器规则。** iPhone Agent 默认可使用对话级持久 `browser_use`，只有用户明确要求离线或不要浏览时才隐藏。页面限定为公开 HTTPS，支持搜索、导航、读取、查找、普通点击、非敏感字段输入、滚动和标签管理；不自动登录、不输入密码/验证码、不提交表单/高影响操作，不提供 Cookie、任意 JavaScript、下载或页面截图回传。上述安全范围内操作不逐次审批，真实动作进入活动详情。模型工具和 iSH `openmuse-browser-use` 共用同一 conversation-scoped 标签池，已在 T62 真机验证。搜索 Google 优先；失败时切换用户设置的备用引擎并注明来源，全部失败则如实报告。

**保留审批的操作。** 正式记忆/文件/共享资料写入仍按具体写入逐项预览确认；本机工作区的临时草稿写入逐项确认；尚未接入的发送邮件、预订、支付、删除外部资料等副作用未来应逐项确认。用户主动保存明确个人事实、已确认偏好的自动记忆按 D21 规则可撤销，不需要另加通用工具弹窗。公开 HTTPS 浏览及普通页面交互，与登录/提交/购买等高影响动作使用不同权限边界。

这是 T54 的已落地策略。其原则是把“读取公开网页”从“运行任意命令”中分开，减少无意义弹窗，同时保留对执行代码和修改正式资料的确认。OpenMinis 的上游具体权限模型与本地实现对照见 [OpenMinis 浏览器与权限对照](OPENMINIS_BROWSER_PERMISSIONS_2026-10-11.md)。

### D34–D37 已确认目标

用户已确认将手机权限调整为风险分层：模型按任务自动选择本机普通隔离工具，不要求用户点名 iSH；普通隔离运行、iSH 出站网络和公开 HTTPS 浏览器的安全范围内动作均不逐次审批；日历、照片、位置、剪贴板等敏感 iOS 数据按类别授权；正式记忆/共享资料变更，以及通过 OpenMuse 原生工具进行的发送、购买等外部高影响操作仍需确认。D35 要求 Google 为默认搜索，Google 不可达时切换到用户设置的备用引擎并标明来源；无备用时报告不可用。D36 要求从现有活动记录进入工具执行详情，不另加消息胶囊入口；D38 补充详情应保留每次调用的编号、执行设备、参数、返回/错误、状态与耗时。工具详情已覆盖当前开放的手机工具和 Mac Pi 只读文件调用；上游专属富内容视图与真机活动详情差异仍需继续验收，见 [T56](ITERATIONS.md)。

**D37：iSH guest 任意出站网络不额外审批。** 用户明确要求与 OpenMinis 一致。guest 能把当前对话挂载区可读内容发往互联网，也可自行提交 HTTP 请求；不为每条命令或网络请求弹窗。运行时继续限制 guest 目录边界、命令长度、时长和输出量，附件只读，正式记忆、数据库、Keychain、Mac 文件和其他 App 私有目录不挂载。此处没有对 guest 内任意网络写操作的硬拦截；系统提示对高影响操作的约束不能被表述为强制技术控制。正式记忆/共享工作区写入仍由 Swift 宿主逐项审批。公开 HTTPS 浏览器仍是单独的受限工具，与 guest shell 网络能力分开管理。

### D38 活动详情的逐次工具记录

用户要求活动详情保留 OpenMinis 工具胶囊面板的操作记录和检查能力，同时沿用 D36 的活动记录入口。每次工具操作应显示工具名、稳定调用编号、执行设备、脱敏后的调用参数、返回内容或错误、状态、开始/结束时间及耗时；可以展开内容并复制详情。活动摘要与操作详情分开保存，避免长结果撑大单条任务记录；操作详情随现有认证设备同步与归档迁移。

日志可能含私人网页文本、命令和用户文件内容；只存到私有工作区，不能进入公开日志、Issue 或虚构数据测试之外的仓库样本。保存前遮盖常见 API key、Bearer、密码、token、secret、cookie、authorization 字段；参数上限 8 KiB、返回上限 16 KiB、错误上限 2 KiB，超限写明截断。脱敏规则不可能识别所有秘密，不能承诺“日志绝无敏感内容”。OpenMuse 只展示当前工具真正返回的数据，不仿造上游尚未提供的数据，如网页截图、交互浏览器接管和文件编辑差异。

实现/验证记录见 [T55](ITERATIONS.md) 和 [T56](ITERATIONS.md)；上游源码与 iPhone 实测记录见 [OpenMinis 活动详情对照](OPENMINIS_ACTIVITY_DETAILS_2026-10-11.md)。

## 外部资料只读连接器

Notion 凭证只进入本机钥匙串；搜索与块读取使用只读 API，请求只涵盖连接器可访问且用户明确选择导入的页面。Obsidian 只读取系统文件选择器中明确选中的 Markdown 文件，不扫描整个 Vault，也不上传本地完整路径。QQ 邮箱只连接 `imap.qq.com:993` TLS 收件箱；需使用用户在 QQ 邮箱生成的 16 位客户端授权码。当前最多读取最近 14 天、每次最多 20 封的邮件头和 2 KiB 纯文本摘录，不读取附件，也不发送、移动、标记或删除邮件。

连接器读取结果先展示标题、来源和正文预览，用户选择后才写入结构化来源/导入记录。邮件、网页和笔记正文都作为不可信外部资料，不可改变权限或系统指令；只有与当前请求匹配时才进入模型上下文。凭证不随工作区同步或导出。用户删除导入资料时，OpenMuse 删除本机内容、来源和导入记录，并向已配对设备同步只含 ID 的删除标记；外部原文不受修改。QQ MIME 解析现有协议桩覆盖常见纯文本格式，但真实账号邮件的解析表现、授权撤销和网络可达性仍需实际设备验收。

## 2026-10-10：近期对话回顾实现切片

身份与记忆页提供“回顾最近对话”。可选每日自动回顾默认关闭；开启后最多每天成功一次、失败最多再尝试一次，安静时段默认 22:00–08:00。iOS 会在安静时段结束后请求一次机会式后台刷新，也会在 OpenMuse 启动时检查漏跑；系统可能延后或不运行，用户强制退出后也不能保证唤醒。手动回顾不受安静时段限制，但仍受每日频率上限约束。

回顾输入限最近 7 天、最多 24 条原创消息和 8,000 个字符；最多生成 5 条建议，模型输出上限 900 tokens。请求只走已配置模型 API，不获得 Pi 文件工具。运行记录保存来源消息 ID、输入摘要、模型、实际 token 用量和结果；不保存发送给模型的原始回顾文本。建议可为待确认事实、理解假设、协作习惯或明确进行中目标的一条小步骤，均须用户逐条采纳。前三类分别进入 USER.md 结构化记忆或 SOUL.md；目标步骤只有在目标仍进行中且来源仍属于该目标对话时才能追加为新 GoalStep。该动作不改变目标状态、不设提醒、不调用外部工具。采纳记录可撤销/忘记。排除 ChatGPT 导入会话、未知来源引用和仅由助手消息支持的主张。

这一切片不是预算系统：token 上限和每天一次限制了请求规模与频率，但没有货币额度、输入成本预留、跨设备额度分配、后台任务恢复或完整 HEARTBEAT 调度。自动功能默认关闭，开启会把选定范围内的近期对话和已确认记忆发给当前模型服务；iOS/macOS 两端真实联网与锁屏行为仍待设备验收。

## 2026-10-10 实现状态：记忆彻底遗忘切片

记忆页区分“撤销并保留历史”和用户主动确认的“彻底忘记”。后者从本机删除结构化记忆、修订、冲突与旧同步载荷；当前 USER.md 投影及历史载荷会清理；同步墓碑不含记忆原文，旧写入及较早工作区包不能复活该条记忆。来源聊天仍保留，离线设备在下次同步前仍有副本，OpenMuse 管理范围外的手动导出文件不会被删除，独立导入到没有新墓碑的设备也无法知道别处发生过遗忘。旧版客户端不理解新墓碑事件，需升级后再同步。上述行为有本机合成 Core 测试，未做真机跨网验收；范围预览、受控备份删除和源聊天选择删除仍未实现。

2026-10-11 补充：手机模型回合执行或等待工具审批时不允许切换或新建对话。这个锁定只保护当前活动回合的来源与写入目标，不会授予后续工具操作权限。

## iPhone 原生闹钟与计时器（D44）

`openmuse-alarm` 在 iSH guest 中提供设置、列出和取消闹钟/计时器的窄用途入口；iOS 26+ 通过 AlarmKit 执行，第一次使用时由 Apple 的系统授权弹窗征求许可。OpenMuse 不再叠加逐条确认。授权拒绝时必须返回失败，不能说闹钟已创建；不支持 AlarmKit 的系统也不能以普通通知替代。

该授权只覆盖本 App 创建的系统闹钟，不授予读取日历、提醒事项或其他 App 数据的权限。`cancel all` 仅取消 AlarmKit 向 OpenMuse 当前客户端返回的闹钟。用户聊天和活动详情记录具体命令、系统结果及失败；系统闹钟本身是设备状态，不进入工作区备份或跨设备同步。目标提醒仍沿用原有目标/通知流程。OpenMinis 固定提交中的实现和 Apple 授权要求见 [端侧运行时对照](OPENMINIS_PHONE_RUNTIME_COMPARISON_2026-10-11.md)。
