## 结论

已确认的一期能力均仍在需求范围内，没有发现被悄悄删除的目标、动态、记忆、点子、连接器、双端、模型、Pi、构件或执行记录需求。当前实现比早期状态多出本地事件同步、JSON 迁移包、RSS/Atom 兴趣动态、流式直连和 token 用量记录；这些只覆盖部分需求。一期整体仍未通过验收。

这次发现并补入两项需求表达缺口：

1. 最初提出的“中国使用 Muse 需要翻墙”没有被单独写成产品验收项。现新增 CN1：OpenMuse 的直接手机使用及首轮 DeepSeek 路径要在中国境内常见网络上验证，不依赖 Muse 服务或商业 VPN；可选 Tailscale 连接家中 Mac 是另一条需要单独验证的路径。
2. 用户后来明确要求尽可能像素级还原 Muse。旧 UI 规格只要求逐页结构/间距对照，未写清截图比较验收。现已在 UI_SPEC 加入同设备截图叠加/差异检查要求；当前仍未完成像素级视觉验收。

另发现 PRD、PHASE1_PARITY、MEMORY_STORAGE、IOS_BACKGROUND 的部分状态文字仍停留在 D31 授权实现之前，容易误读成尚未授权。它们已更新为当前状态，早期过程记录仍保留。

## 状态含义

- **部分实现**：源码有对应切片，但没有覆盖完整需求或缺少关键路径验证。
- **未实现**：当前源码没有该能力；空页面、模板或文档方案不计为实现。
- **待真机验证**：有代码或模拟器/本机证据，但不能证明真实 iPhone、蜂窝网络、后台或跨设备结果。
- **方案已写、尚未实现**：规格存在，产品能力还没有。
- **已通过的局部检查**：只表示该行所写的范围通过，不代表整个需求通过。

## 代码检查发现的行为风险

以下是当前仍未解决的风险；已通过本次新增回归用例修复并验证的部分已从风险项移出。

- 旅行构件按文本中的不同分日标题识别草稿，并将回复正文保存为文本；当前结构校验不核验目的地事实、营业时间、价格、交通、天气或预订，不能把来源消息 ID 当作外部事实来源。

目标和记忆入口现为有限、显式句式/Markdown 规则分类器，不应描述为通用意图理解。检索增加了人工维护的本地概念别名，可覆盖已列出的同义改写（例如“出行”召回“旅游”），但无法理解任意语义、时间和上下文；2026-10-11 的专项回归确认这个例子，并重测既有敏感过滤与导入/当前对话排除。2026-10-11 之前的 88 项专项结果为86通过、2项因缺少实时Pi/Tailscale端点跳过、0失败；本轮新增范围的最新结果见 T32，不能把定向测试推广成完整Core/UI验收。明确事实自动捕获只覆盖已编码句式，普通自然表达可能留在聊天历史而不成为结构化画像。SOUL/IDENTITY/AGENTS 已改为受明确范围约束的 system prompt 设置；用户编辑内容仍需用真实模型验证提示注入和权限声明的实际行为。敏感标记依赖标题和关键词，不等同完整隐私识别，导入预览需由用户逐条检查。

这些风险不等于用户需求缺失；它们是已写入需求但当前实现尚未满足的行为缺口，应在下一轮按主体识别/纠正/来源验收补测试。
