# Muse参考页面与交互规格 v1

2026-10-10。本轮实际查看10张归档图，按用户指示直接以既有Muse页面和交互元素作为设计基线；用户明确要求尽可能像素级还原。此前只完成首屏比例调整，尚未完成逐页像素对照或原版动画还原。原始图仍私人，公开规格使用合成内容。设计遵循DESIGN_PRINCIPLES。

## 共用组件

iPhone：聊天顶部为左侧栏按钮和右侧本页操作，两个按钮保持对齐并比旧版下移约13pt；消息可滚动到透明顶栏下方，只有圆形操作按钮有半透明材质。聊天页不放 OpenMuse 头像/名称入口，也不把名字做成按钮。任务阶段在 iOS 17+ 通过锁屏 Live Activity 与 Dynamic Island 显示；回复与活动记录内继续展示具体进度。底部五入口胶囊导航，最右侧“我的”使用 person.crop.circle 作为普通 Tab 页面切换，页面内保留活动/批准/桌面端/近期/身份五个子页；离开此页使用底栏切换，不显示上拉 sheet 的关闭控件。选中项有独立深色背景；黑/中性背景、灰色面板、蓝色动作作为深色基线，浅色采用语义色。字体跟系统，主要触控目标至少44pt，安全区/键盘不遮操作。卡片圆角、边距和字体先用统一token，实施时与本地图片逐页核对，不编造截图精确尺寸。

头像使用原创占位/素材；工作、等待、完成/空闲、失败/断开映射真实状态。拟定过渡150–250ms、减少动态效果时静态切换（项目候选值，不称Muse原参数）。等候不做假百分比。活动标题、阶段、时间统一数据源，详细记录按需展开。

## 状态与操作规格

每页覆盖正常、空、加载、失败/重试、待同步；执行另含等待用户/电脑/网络、系统暂停、取消待确认。错误给原因和可做动作并保留输入；不可用操作不靠颜色暗示。模型未配置先设置/测试，可跳过连接器但不能假装可发模型消息。首次轻松旅行按ONBOARDING_TRAVEL，不据现有账号图假定已见Muse注册流程。

审批页展示具体动作、资料范围、目标设备、完整待写正文、确认/拒绝；拒绝产生有效活动记录并把拒绝结果回传模型，不继续动作。当前已实现的审批范围是 iPhone 当前对话隔离工作区的单次写入；批准不会变成长期授权，Mac 文件写入、支付、发信、浏览器/桌面操作尚未开放。电脑页以连接和任务控制为主，浏览器画面只有真实实现该工具后才显示；长期完整桌面不画成一期可用功能。

Mac采用同样五模块侧栏+详情，聊天中同一头像活动入口；长表/成果可开更宽详情，快捷键与原生窗口行为；Mac布局是本项目适配，现有iPhone图不能证明Muse Mac行为。

## 视觉与可用性验收

逐页看相应原图→合成旅行数据实现→同一设备/视口截图叠加或差异检查布局、控件大小、层级和间距；保存页面、状态、设备、构建版本与偏差，修正后复测。正常/加载/错误/键盘路径分别走。检查五入口、旁聊草稿、表格展开/宽表、取消保存、头像层级、返回位置、大字号/VoiceOver/减少动态效果。用户无额外说明能找到发消息、看任务、改记忆、打开成果四项入口；困惑记入迭代并修正。不为开工额外制作另一套脱离截图的高保真稿；这份规格+私人证据即初期界面基线，公开展示图实施时用合成素材生成。不同设备截图缩放、字体栅格和系统版本可能产生像素差异，应区分布局偏差与抗锯齿差异；当前尚无截图差异验收记录。

## 2026-10-13 Dynamic Island 状态

iOS 17+ 的 Live Activity 与 Widget Extension 在锁屏和 Dynamic Island 显示 OpenMuse 和真实阶段状态，不携带聊天正文或工具内容，不伪造百分比。运行中使用不确定进度指示；过期状态显示“进度暂时没有更新”；完成、失败、取消后显示终态并收起。Live Activity 关闭或不可用时，应用内活动记录仍可查看。它不保证锁屏续跑或后台唤醒；真实设备视觉验收状态见 T85。

## 2026-10-15 目标删除、兴趣动态与活动布局

目标卡的更多菜单包含“删除目标”，通过原生破坏性确认后删除该目标及相关提醒/进展；聊天中只有用户本轮明确要求删除时才提供 Agent 删除工具。重复目标先按来源和置信度辨别，不能唯一确定则询问。执行中或等待中的关联任务会阻止删除。详情见 PRD 第29节与 [T89](ITERATIONS.md#t89)。

主聊右上角菜单只保留“新建旁聊”，不再显示功能相同的“新对话”。“最近活动”以全高、大尺寸、不透明背景和独立滚动区域呈现；标题和第一项必须避开系统状态栏，列表能够完整滚动。自动化以可访问标识 `activity-list-scroll` 检查。

动态以内容卡片作为主要阅读区域。顶部保留可编辑的兴趣说明；手机打开页面时在到期后自动用持久浏览器搜索公开索引，用户仍可手动刷新。卡片展示搜索结果真实标题、域名、可得摘要和原文链接；RSS/Atom 的添加与管理放在折叠的“订阅来源（可选）”内。查询仅带非敏感兴趣、活动目标标题和说明，不发送聊天原文。缺少结果时明确显示搜索状态，不展示虚构文章。此流程目前是 iPhone 的 Google/备用引擎搜索，不是平台原生 API；Mac 可看同步结果和配置订阅，不能自动发现。Muse 动态页静态参考实际查看 `.research-local/muse-ui/2026-10-10/screenshots/20261009T162900548640Z-2b1d9017.jpg`：顶部显示动态标题和简短兴趣说明，正文直接呈现带来源与摘要的兴趣内容，订阅管理不占主要阅读区。参考只确定页面层级，不推导未观察到的后台算法。

新安装时的 `SOUL.md` 正文采用用户提供的英文 OpenMuse persona 模板；“About this file”作为只读编辑说明显示在正文上方，明确不会保存进文件。模板只用于缺失文件，不能覆盖用户已编辑的人格。实现/回归范围见 [T89](ITERATIONS.md#t89)。
