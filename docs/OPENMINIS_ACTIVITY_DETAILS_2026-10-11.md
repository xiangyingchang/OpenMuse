# OpenMinis 工具胶囊与活动详情对照

查阅日期：2026-10-11。源码固定在 `OpenMinis/OpenMinis` commit `b4c0661d5631ebab4d1a2e6f3fd4c805d4030a6c`。本笔记只描述公开源码能证明的界面和数据流，不把上游实现等同于 Muse 的云端机制。

## 用户能看到什么

聊天中每次工具调用显示为可点击的胶囊。胶囊以工具种类配图标，显示简短名称、运行状态；运行中有动态点和停止按钮，完成后显示耗时。点击后打开单次工具详情，而不是只展示一条自然语言摘要。

长按菜单的“Copy Tool Details”会复制工具名、格式化的输入 JSON、返回文本和状态；当消息正文为空时可从工具快照补足结果。点击打开详情、复制工具调用参数与结果的逻辑位于 [AssistantBlockView.swift](https://github.com/OpenMinis/OpenMinis/blob/b4c0661d5631ebab4d1a2e6f3fd4c805d4030a6c/src/ios/Views/Chat/AssistantBlockView.swift)。

详情面板按工具类型呈现内容。上游代码注释和视图实现列出 shell 输出、文件编辑/写入、浏览器快照、记忆修改和图片；浏览器 URL 可复制，shell 链接可点开；部分长输出采用分块延迟展开，避免大文本一次性压垮主线程。面板也提供前后操作导航、开始时间和运行时长；运行中显示已用时。详见 [ToolLiveSheet.swift](https://github.com/OpenMinis/OpenMinis/blob/b4c0661d5631ebab4d1a2e6f3fd4c805d4030a6c/src/ios/Views/Chat/ToolLiveSheet.swift)。

因此，“胶囊”是紧凑入口；核心信息是每次工具操作可追溯的名称、参数、结果/错误和执行状态，特殊工具再使用专门的富内容视图。上游这两份 UI 文件不能证明历史保留期限、数据库同步方案或后台保证。

## 与 OpenMuse 的差距

OpenMuse 原先的 `ModelToolExecutionEvent` 只有调用 ID、工具名、可选相对路径、状态和安全摘要；`ActivityStepRecord` 只有分组、标题、摘要、状态与更新时间。因事件本身不携带模型传入的参数和工具结果，活动详情无法还原 OpenMinis 胶囊面板中的逐次执行细节。

用户保留了 D36 的入口选择：从头像进入既有活动记录，不增加平行消息胶囊；D38 要求活动详情内保留胶囊能查看的同层级操作记录。实现把活动概览与逐次详情分开存储，记录工具名、参数、返回/错误、状态及起止时间；详情支持展开和复制，活动仍由本设备执行时可停止当前回复，并通过现有本地数据库、设备同步与归档链路持久化。停止通过当前回复取消机制执行；已经委派到远端 Mac 的任务可能继续运行。

OpenMuse 当前工具只输出文本/JSON。它不会伪造浏览器截图、交互式页面接管、编辑差异或图像专属视图；这些能力只有在对应工具真实生成可保存的数据后才能对齐。

## 记录隐私和容量

调用参数、shell 输出、网页正文及 Mac 授权文件结果都可能包含用户资料。它们会进入私有活动数据并随活动同步到用户已配对的设备；不要用真实隐私内容写公共测试或公开日志。保存前遮盖常见 API key、Bearer、密码/token/凭证字段；每次调用的参数最多 8 KiB、返回最多 16 KiB、错误最多 2 KiB，超出部分显示截断标记。该规则只能识别常见凭证形式，不能保证发现所有秘密；被记录的非凭证内容仍按私有数据处理。

真实工具结果事件、详情 UI、同步/重开和凭证脱敏的验证状态见 [T55](ITERATIONS.md) 与 [活动详情政策](POLICIES.md)。模拟器构建不能替代真机打开活动详情验收。

## iPhone 实机对照

2026-10-11 在用户已连接的 iPhone 上打开已安装的 OpenMinis，只检查现有的 Shell 测试调用，没有发起新请求或运行命令。聊天内胶囊显示终端图标、`Check shell environment works` 和 `0.5s`；点开后出现单次调用面板：顶部有关闭、居中标题 `Minis 电脑` 和终端入口；正文用终端黑底显示完整命令与 Shell 输出；底部固定显示成功状态、`Minis is using Shell`、调用摘要、耗时、完成时间及前后调用导航（本次为 `1 / 1`）。该面板当前没有可见的复制按钮；源码中的长按胶囊菜单负责复制完整调用详情。

实机只观察到这一条既有 Shell 调用，因此浏览器、文件差异、记忆和图片详情仍由固定源码确认，不能算作本机实测。截图留在本机 iPhone-use 产物区，没有放入公开仓库；本机文件为 `~/.local/share/iphone-use/artifacts/20261011T083630759838Z-0324edcd.jpg`。它用于记录上述层级和布局，不作为私密内容或可公开 UI 资产。

这次对照进一步明确了 D38 的数据完整性要求：除工具名、参数、结果/错误、状态和起止时间/耗时外，每条操作还需保留稳定的模型工具调用编号和执行设备。OpenMuse 在现有活动详情里展示这两项，并在复制内容里一并保留。T57 为 iSH 增加运行中输出快照：iSH bridge 约每 250 毫秒读取累计输出，活动操作记录在命令结束前即以 `running` 状态更新；活动详情可读取这份进度。Core 测试覆盖执行中已保存的中间输出，iPhone 真机确认命令完成后详情显示工具名、调用编号、设备、完整命令与真实返回内容。此次没有在命令仍运行时实际打开手机活动详情，因此“运行中页面逐块刷新”的设备 UI 验收仍待做。OpenMinis 的终端黑底视图、浏览器截图、文件差异和图片预览属于按真实数据类型渲染的视图；OpenMuse 只有在对应工具实际提供结构化数据后才逐类实现，不能把纯文本包装成截图或差异。

## 2026-10-11 浏览器操作记录真机验收

用户要求浏览器由模型操作持久标签，并在现有活动详情里保留与 OpenMinis 同层级的操作细节。首次真机检查发现详情 sheet 默认停在中高度；展开后虽然无障碍树包含调用参数，屏幕却把内容裁在可视区下方。OpenMuse 已改为默认全高，并将执行进度和工具时间线放在同一个滚动区域。

签名版重新安装后，iPhone 15 Pro Max 上的活动详情清楚显示“浏览器操作”、`cn.bing.com` 来源、已完成状态和耗时；展开记录后能看到工具名 `openmuse_phone_browser_use`、稳定调用编号、执行设备 `iPhone`、动作 `search`、查询词、`tab_id=1` 和本次返回内容。截图留在本机 iPhone-use 产物区，未复制到公开仓库。模拟器 UI 自动化还验证了参数/结果字段及复制按钮在滚动后可达并可复制。

详情默认采用全高面板是为长工具输出提供空间，不改变 D36 的入口：仍从头像的活动列表进入，不在消息下新增独立胶囊。公开网页返回和搜索词仍按私密活动资料处理；网站 Cookie 与 localStorage 是否跨 App 重启保持没有在本次操作中单独检查。
