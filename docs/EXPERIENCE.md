# 交互与典型旅程

日期：2026-10-09。以下为 OpenMuse 交互建议，尚非最终视觉稿。参考 [Muse 官方设计说明](https://introducing.muse.ai/)，不复制其品牌资产。

## 信息结构

| 入口 | 内容 | 核心动作 |
|---|---|---|
| 聊天 | 持续主对话、头像与正在做的事、插入的卡片 | 连续发送、打断、补充、恢复 |
| 目标 | 自动发现的目标与下一步 | 改计划、暂停、纠正、完成 |
| 兴趣动态 | 与当前生活和目标相关的内容 | 继续聊、练习、不感兴趣 |
| 点子 | 根据了解形成的建议 | 接受、调整、搁置、拒绝 |
| 陪伴者页面 | 身份、活动、记忆、权限、连接器与设置 | 了解、纠正、撤销、导出 |

iPhone 主导航的具体排列待低保真稿讨论。macOS 保留同一结构，在侧栏和详情区展示，避免把工程目录和终端当作用户必须理解的主流程。

## 第一次见面

先给一个暂定名字和自然问候，只问少量能立即帮助用户的信息。用户可以先聊，不强迫填写完整画像或连接全部账号。模型配置必须给清楚的测试结果；无可用模型时说明原因并保留草稿。

首次建立记忆后能看到“我目前知道这些”；可以纠正。高级运行环境和模型参数放到设置，不抢占陪伴体验。

## 英语学习的连续旅程

1. 用户自然说想学英语，系统主动记录并简短说明。
2. 系统了解英语用途和一天能投入的时间，避免一次抛出十个问题。
3. 给出第一周可以执行的小计划，目标页出现下一步。
4. 兴趣动态给出适合用户水平的材料，说明来源和推荐理由。
5. 用户在内容上继续讨论、练习，进度回到原目标。
6. 用户说最近加班，系统更新短期状态并调整计划。
7. 合适时跟进；用户关闭跟进后停止主动消息。
8. 满足约定的完成标准后总结成果，再由用户决定下一目标。

## 结果与控制

聊天卡片分别承载内容、目标调整、记忆变化、点子和需要批准的外部动作。卡片显示实际结果，不把“正在执行”装成完成。

点头像查看活动；区分正在执行、等待网络、等待设备、系统暂停和等待用户。活动记录是可解释的操作摘要，不展示模型隐含思维过程。

设备不同步时显示最近同步时间与本地待同步状态；iCloud 失败时可以继续本地聊天。手机独立任务与 Mac 专属任务要在界面上区分能力。

## 通知与主动性

目标追踪默认主动；追踪强度、内容推荐、点子消息和安静时段可单独调整。只在进展、变化、需要用户行动或约定提醒时打断。具体通知默认值待讨论，不推断用户愿意接受全天候催促。

用户应能一句话说“最近别催我”并看到其生效范围；同样也能通过确定的控件暂停。后台没跑成不能伪造成“已经检查过”。
