# Muse Spaces、语音与主动运行

查阅日期：2026-11-15。来源级别：Meta 官方产品公告与 Muse Code 官方变更记录。本文是公开资料的原创分析，不是消费者 Muse App 源码审计、运行实测或 OpenMuse 实现说明。

## Muse App：Spaces 成为可持续使用的个性化工作区

Meta 于 2026-11-06 介绍 Spaces：用户描述一个想法后，Muse 会在 App 内构建一个可反复使用的自定义体验。官方举例包括行程规划、购物清单、婚礼筹备和音乐追踪。用户可以把 Space 放进侧边栏或主 Tab、移动或隐藏，并设置它何时出现；连接所用 App 后，Space 会在后台保持更新，用户也能直接勾选、记笔记和编辑。

这表示 Muse 的主动帮助不只是一条推送或一段对话，也可以成为长期存在、可定制并持续刷新的工作界面。它与“动态/兴趣发现”不是同一概念：动态侧重发现和消费内容，Space 更像围绕具体兴趣或任务组织的可交互工作区。**研究推论：**OpenMuse 设计这两类能力时应先分清各自的目的；Space 的持久呈现、摆放和后台更新值得参考，但不能据此把 RSS/兴趣流直接改造成任务面板。

官方公告没有说明 Space 的持久化 schema、刷新调度、失败恢复、变更历史、多人共享权限，也没有说明它是否会自动从聊天中推导用户兴趣。公告所说的“围绕日常、目标与兴趣塑造”是产品描述，不足以证明具体记忆写入机制。

## 语音与头像：交互表达增强，不等于人格记忆演化

Meta 于 2026-11-05/06 宣布在 Muse App 推出实时语音与表情头像：语音可打断、头像会随聆听和说话作出表情或动作；用户可以选择只听语音、在聊天旁显示头像或进入全屏。公告称该功能首先在美国的 Muse App 上推出，并计划扩展到 AI 眼镜和 Muse Charm。

这为“陪伴感”增加了实时语音和非语言反馈，但语气、声音选择与头像表情属于呈现层证据，不能证明稳定 SOUL 如何保存、从对话学习或自动改写。也没有新增 Muse 使用周期性 dreaming 的证据。

## Muse Code：目标调度和后台等待的公开运行模式

截至查阅日，Meta 官方 Muse Code 变更记录最新显示 1.4.18；2026-11-01 保存的页面最高为 1.4.13。新页面包含 1.4.14–1.4.18 条目，但未给出各版本的发布日期，因此这里只报告本轮核对到的版本增量，不推断具体发布日期。

- 1.4.15 增加创建目标或定时任务后的提示，并可用 `/cron` 列出或移除计划任务。
- 1.4.17 的更新描述：当只剩后台工作时，会结束当前回合而不是持续轮询；后台工作完成或卡住时再唤醒代理处理结果。这是公开的事件唤醒模式线索，不代表消费端 Muse 的调度实现。
- 1.4.18 调整目标和验证提醒的日志保留方式，以减少会话占用的磁盘空间。

**研究推论：**主动工作可以拆成明确的目标/计划记录、后台执行和事件触发的结果处理；避免把后台任务做成模型持续空转。此运行模式与记忆反思仍是两条链路：定时任务刷新 Space 或推进目标，不等于从对话中提炼长期记忆。

## 对 OpenMuse 研究的影响与边界

1. 后续讨论主动内容时，区分“发现流”和“个人工作区”：前者回答值得看什么，后者承载可继续编辑和回访的任务或兴趣项目。
2. 若设计后台更新，研究其用户可见的计划、状态、刷新结果和失败恢复；Muse Code 的事件唤醒仅作为技术产品参考，不能宣称消费者 App 也如此运行。
3. 将记忆事实、Space 内容和展示偏好分开研究。现有公开材料仍未披露消费端的记忆文件/schema、冲突合并、遗忘传播或 dreaming 算法。
4. 将头像/语音偏好视为交互配置；SOUL 的长期变化仍需单独的写入证据和用户可见确认机制。

本轮没有操作 Muse App 或用户账号，也没有对上述新功能做用户实测。所有产品能力均按官方公告记载；设计建议和上述差异判断均为研究推论。
