## 持续更新方式

每周检查一次社区仓库版本与 Muse 官方设计/技术资料；方案迭代前也检查相关证据。先比较文件变化，再有针对性阅读，记录新增/修改/撤回、旧与新 commit、来源等级和对 OpenMuse 的影响。不要覆盖原快照，不重复归档整个仓库。

每条结论标明：来源描述、研究推论、用户实测或待验证。用户观察记录日期、平台/版本（如果知道）、触发与结果；缺版本则写未知。私人截图、原始聊天和实际记忆留在本地，不自动发布；公开只写合成场景或经确认可公开的归纳。

没有实质变化无需通知。发现会改变存储、人格演化、主动工作或首聊方案的变化时，更新研究文档并向用户说明。研究更新不自动批准应用实现或锁死候选方案。
