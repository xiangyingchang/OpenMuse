# 本地截图如何用于设计与验收

日期：2026-10-10。本文件是 OpenMuse 的设计协作约定；私人原件只在本机，公开仓库提供使用方法，不提供原件。

## 查找位置

从 OpenMuse 仓库根目录进入 `.research-local/muse-ui/2026-10-10/`：

- `INDEX.md`：按页面与观察轮次列出截图链接，先从这里选图。
- `MANIFEST.json`：截图路径、页面说明、UTC 时间与 SHA-256 校验值。
- `screenshots/`：原始 JPG。

当前归档为 78 张。截图文件名采用 UTC，本次观察发生在上海 2026-10-10 凌晨。原始工具产物另存在工具目录，日常参考以此项目归档为准，避免依赖临时工具文件。不要凭文件名时间推断 Muse 版本；应用版本此次未核验。

## 每次设计或实现的使用顺序

1. 先读 [交互档案](IOS_INTERACTIONS_2026-10-10.md)，确定页面、路径、已观察状态和未知操作。
2. 从本地 `INDEX.md` 找对应页面，实际打开图片查看；只读索引文字不算看过截图。
3. 对照图片登记导航、控件位置/层级、文案、颜色、圆角、间距、滚动、遮挡、键盘与加载状态。静态图不能证明动画曲线、点击后的动作或后台机制。
4. 在设计说明中引用需求 ID、观察章节和本地截图文件名。公开文档可注明研究日期/页面/状态；不粘贴私人内容或将原图作为公开资源。
5. 用虚构数据、原创资产做 OpenMuse 页面。截图用于交互和视觉参考，不直接复用 Muse 头像、图标或用户的媒体、聊天和记忆。
6. 在对应设备上走相同路径，核对布局与状态，同时按需求验证行为。视觉对照和功能/后台验证分别报告；不能凭相似画面宣布机制对齐。

优先映射：V1a 聊天与旁聊 → 主聊/引用键盘/旅行旁聊；V1b 目标 → 列表/详情；V1c 动态 → 内容/指令编辑/推荐解释；V1d 点子 → 列表/详情/菜单；V1e 资源库 → 构件/影音/预览；V1f 身份 → SOUL/MEMORY/编辑态；V1g 执行 → 活动/批准/桌面/近期/浏览器控制。ID 定义见 [一期对齐清单](../PHASE1_PARITY.md)。

## 缺失、迁移与更新

`.research-local/` 已被 Git 忽略；公开 clone、新电脑或云端开发环境不会自动得到这些图片。找不到原件时，明确标为“缺少本地视觉证据”，不要声称已看过或补造细节。可以继续依据公开文字设计，再请用户连接手机补看需要的页面。

换电脑若需要原件，由用户选择私人传输/备份方式；不上传到公开仓库、Issue、PR、公开设计平台或外部服务。当前未另行创建备份，也不能从 Git 恢复图片。

新观察使用新的日期目录或观察轮次，更新索引与校验值，保留旧原件和结论，标注变化。截屏含健康、关系、账号、证件缩略图等私人内容，不默认获得公开或传给其他供应商的授权。必要的公开设计图用合成数据重绘；若要发布实拍图须另行确定脱敏与发布范围。

## 还需补验的优先级

| 优先级 | 具体验证 | 目前缺口 |
|---|---|---|
| 先补 | 旅行是否写入目标，约束改变如何更新 | 助手口头说关联，不等于目标记录已核对 |
| 先补 | 行程修改、保存为构件、旁聊与资源库往返 | 目前完成的是聊天草案，不是独立构件闭环 |
| 先补 | 记忆纠正、遗忘、人格变化告知 | 已看正文和编辑态，未做受控写入/遗忘 |
| 后续场景 | 待审批、拒绝、停止与恢复、离线/通知 | 只验证本次浏览器启动和停止；不能推广至全部工具 |
| 后续场景 | 首次引导、语音、消息菜单、选择卡点击 | 现有账号和当前工具未覆盖全部操作 |
| 实现技术关卡 | Mac Pi 与手机接管、后台、iCloud 冲突、模型切换 | Muse UI 无法证明 OpenMuse 的执行方案可行 |

前两项可沿当前旅行旁聊验证；记忆写入/遗忘需使用专门测试内容，避免污染或删除真实资料。全部验证不是开始设计的前提，但一期关键行为必须在相应实现前明确，并在交付时有实际证据。
