# 通过实际场景核对 Muse

日期：2026-10-10。用户授权在后续迭代中询问 Muse 的类似场景处理。每轮优先问一个当前最影响设计的问题，不要求用户专门制造测试，也不把推断登记为实测。

| 设计环节 | 可以向用户核对的问题 | 观察重点 |
|---|---|---|
| 记忆纠正 | 你纠正一个它已记住的偏好后，文件和后续建议怎样变化？ | 生效时间、来源、旧记录、告知 |
| 范围识别 | “这次不想早起”被记成旅行约束还是长期偏好？ | USER/GLOBAL 的变化与后续表现 |
| Dreaming | 一次聊得不太顺之后，隔天有没有主动调整或修复？ | 实际回应、dreams 内容、是否通知 |
| 人格演化 | SOUL 真正变化时，它怎样告诉你？你能看到差异吗？ | 触发、告知、编辑、撤销 |
| 维护控制 | 说“这件事先放一放”之后，相关研究和主动消息会停止吗？ | 目标、HEARTBEAT、后台状态 |
| 遗忘 | 要它忘记一条信息后，日记或反思里是否还引用？ | 检索、衍生内容、再次导入 |
| 首聊 | 没命名或没连接账号时，怎样引导你完成第一件事？ | 引导顺序、跳过、成果 |
| 导入 | 从其他 AI 导入画像后，哪些内容直接保存，哪些会再问？ | 预览、推断、来源和纠正 |

## 记录模板

- 观察日期与平台/版本（未知则注明）。
- 触发场景：用合成或脱敏描述，不放原始私人聊天。
- 实际行为：发生了什么；哪些只是猜测。
- 文件或界面证据：是否实际查看；没有证据的部分标未核验。
- 对 OpenMuse 的影响：采用、调整、继续研究或不采用，附理由。
- 公开状态：默认私人原件不公开，公共研究只记录允许公开的归纳。

用户不方便提供时保留待验证；研究可以继续，不能以我们的建议补成 Muse 已有行为。
