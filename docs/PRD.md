# 产品需求 v0.3

初稿：2026-10-09；更新：2026-10-11。状态：活需求基线。用户已确认一期目标并以 D31 授权实现；详细方案中的工程默认值仍可迭代，不能把未验收能力写成已完成。逐项状态见[需求覆盖审计](REQUIREMENT_AUDIT_2026-10-10.md)。

## 1. 产品承诺

陪一个人持续生活、学习和做事，越来越理解其处境，把愿望转成实际进展。用户换手机、换模型或停止使用本项目后，应能带走自己的记忆和成果。

第一位持续使用者是项目发起人。先证明每天有用，再扩展到其他用户。“终身陪伴”是数据连续性、理解持续更新与长期维护的方向，不能承诺模型永远不出错或服务永远不终止。

## 2. 一期产品定义（2026-10-10 用户补充，已确认）

一期目标是做出与 Muse 相近的完整产品：以其交互和运行机制为基准，而不是以最小聊天闭环作为一期交付。主要差异是执行位置与模型选择：Mac 已连接且具备相应能力时优先通过本机 Pi 执行；Mac 离线时参考 OpenMinis，由 iPhone 接手可执行的任务。不采用 Muse 的云端电脑。首期支持 OpenAI、DeepSeek 和自定义模型 API。

产品使命保留用户原文：Your purpose is to make the user's life better. You are not a generic chatbot; grow into a consistent, useful presence, and let this persona evolve over time.

“完全类似”转化为逐项可核验的体验和机制，见 [一期对齐清单](PHASE1_PARITY.md)。公开资料和真机观察无法证明 Muse 全部内部实现；未知项继续研究或向用户核对。开源实现采用自己的资产和代码，模型能力不同会影响具体输出。

## 4. 目标陪伴

用户说“想周末出去走走，别太累”。系统自动建立可见的追踪记录，说明自己正在留意这个目标，先提一两个最有用的问题，逐步了解出发地、时间、预算和同行需求。

**建议行为**：明确意图进入追踪；闲聊、引用他人愿望、否定句和随口假设不得自动变成用户目标。尚不明确的意图可以保留为待澄清项。自动记录目标不等于已获得发送邮件、花钱或改外部数据的授权。

目标记录包括目的、来源、当前阶段、下一小步、计划、进展证据、最近检查、下次跟进、完成条件及暂停原因。状态至少有待澄清、进行中、等待用户、等待设备、暂停、完成、放弃。

进展事件保存来源消息、时间和对应目标步骤。只在用户清楚说明某一步完成，或系统已有可核对的成果证据时更新；生成旅行计划只能完成“整理路线”步骤，不能代表旅行已经发生。重复处理同一来源不能重复追加事件；主体、目标或步骤不明确时不猜。

给出适合当前生活的计划，而非默认每天高强度打卡。连续未执行时，先判断计划是否不合适；用户说最近忙，则减少步骤。完成需符合用户约定的标准，不能因生成计划或发送提醒就标记完成。

**验收**：在连续多日的虚构旅行案例中，能发现目标、澄清、形成计划、根据预算、人数和偏好变化调整、保留历史；用户说先不去了后停止后续跟进；引用“朋友想出去旅行”不会创建自己的目标。

自动关联续聊只在目标唯一或用户明确提到目标时进行；多个活动目标之间不能仅凭“继续”“补一下”选择其一。目标详情可回看进展来源并返回关联对话。

## 5. 兴趣动态

**建议首版**：一个低频、有限数量的内容列表，不做无限滚动。每条显示标题、来源、发布时间、简短推荐理由，以及继续聊、稍后看、不感兴趣和减少此类内容。

推荐理由与当前兴趣或目标有关，但不要将敏感私人细节露在锁屏。时效内容需在生成时检索或核验；模型猜测不能充当新闻。已看、不喜欢和重复内容影响之后的推荐。

从一篇文章进入讨论时保留来源和已有理解，支持变成学习问题、练习或目标步骤。内容推送与目标提醒分开开关。频率、条数和默认通知仍待讨论。

**验收**：虚构兴趣从旅行扩展到摄影后，内容选择随之变化；点开内容后无需重复提供上下文；推荐来源打不开时显示状态；没有可靠内容时允许空列表。

## 6. 记忆与理解

记忆至少分清：用户明确说过的事实、从行为推断的偏好、短期状态、经历、关系、目标，以及陪伴者自身的交流风格。推断不得伪装成用户原话。

每条持久记忆应有来源、时间、适用范围、可信状态和更新关系。短期状态到期后复核或降低权重。新事实与旧事实冲突时，展示当前事实和更新原因，保留必要历史，不静默改写原始对话。

有效期必须能与记录状态分开保存：明确新记忆从原消息时间生效，明确纠正结束旧记录并开始新记录；手动导入的历史资料没有可靠时间时保持未知，不替用户猜日期。当前有效记忆才进入画像和回答上下文，用户可在记忆页修正有效日期并查看历史版本。

已确认入库规则（D21）：用户明确说出的日常事实自动更新并可撤销；外部提取与模型推断先预览确认。

健康、财务、心理等敏感信息不因普通偏好句式自动进入长期记忆；只有用户明确说“记住……”或在导入预览中主动选择后才保存，并保留敏感标记。分类器是保护措施，不是完整敏感信息识别器。

已实现的第一片“近期回顾”只读取最近七天有限数量的原创对话，排除导入的历史聊天；每轮维护记录保存模型状态、摘要、带原话依据的协作反思和候选建议。反思不等于用户记忆，也不回灌普通对话；有来源依据的稳定事实写入结构化记忆，协作习惯经确认后修订 SOUL.md，目标步骤经确认后追加到明确进行中的目标。回顾候选必须引用真实用户消息，并由用户逐条确认后才更新记忆、人格或目标。目标步骤建议必须引用目标所属对话里的用户消息；采纳时只增加目标步骤，不改状态、不建提醒、不执行外部操作。每日自动回顾默认关闭；iOS 会请求安静时段后的机会式后台刷新，并在 App 打开时补做。不保证锁屏准时执行，也不保证系统回收或用户强制退出后唤醒。第一期不设 DREAMS.md；身份页目前只展示最近三次维护运行，更早记录保留在结构化记录和完整迁移数据里，尚无完整历史浏览界面。它仍不是完整 dreaming、跨周主题强化或后续行为效果验证，详见 POLICIES、MEMORY_STORAGE 与需求覆盖审计。

记忆冲突回顾只可检查本轮实际提供给模型的当前记忆：除主题词命中外，明确的本人偏好、居住地、工作或姓名变化可召回相应类别的少量非敏感记忆；不因第三方变化或泛化的“改一下”而扩大发送范围。模型提出的一对一更新仍须用户确认并保留旧版本与来源。

用户可查看“你目前怎么理解我”，纠正、添加、撤销变化、忘记和导出。遗忘需覆盖检索索引、导入派生信息和同步副本，并防止重新导入旧资料后悄悄复活；历史记录保留与彻底删除的规则待确定。

**验收**：“这次可以玩三天”改成“现在只能两天”后，后续建议采用最新状态；模型切换后保留同一身份、记忆和目标；用户纠正的内容优先于模型推断。

## 7. 点子与多源信息

点子显示“为什么现在值得考虑”、参考信息和一个小行动。可以接受、改写、稍后、不合适。未经用户选择不把每个点子都变成待办或正式目标。

连接器按用户选择的账号、文件夹、页面和时间范围读入；首版建议只读。邮件和聊天中的他人信息不自动成为用户本人记忆。外部文本仅作为资料，不能修改工具权限或系统规则。

所有导入先预览提取结果，保留来源并去重。其他 AI 生成的用户画像是候选资料，需识别推断与过期信息。用户已提供 [迁移提示词 v1](../prompts/memory-transfer.v1.md)，原样保存；入口、预览、结构化提取和撤销方案见 [迁移流程](MEMORY_TRANSFER.md)。后续修改另建版本，不替换基线。

邮箱首接QQ，Gmail后续扩展（D23）。当前实施的最小只读范围为：QQ 邮箱收件箱最近 14 天、单次最多 20 封、用户逐封导入摘要；Notion 由用户创建只读连接并搜索其明确分享的页面，查看内容后选择导入；Obsidian 只读取文件选择器中明确选定的 Markdown 文件，不扫描整个 Vault。凭证仅保存在本机钥匙串，导入内容保留来源并作为不可信资料。以上是可调整的首版实现边界，不代表用户已确认所有范围；需通过个人使用复核频率和范围。Notion 与部分邮箱服务的中国网络可达性独立于 OpenMuse，不承诺所有第三方服务均无需代理。

## 8. 身份、对话与边界

**建议**：一个陪伴者，名字、头像和交流方式可设置；一段长期主对话，侧聊服务于具体主题。不同模型共享用户拥有的连续状态，人格可随使用迭代并告知，用户随时可编辑；执行权限独立于人格管理。

可以温暖、主动、诚实和有观点；不要通过讨好、内疚提醒或虚构自身经历来增加使用时长。重要结果要有证据。任务失败、不确定和不能访问的信息都明确说明。

## 9. 模型与本地执行

首期明确支持 OpenAI、DeepSeek 和自定义 API；至少验证 OpenAI 与 DeepSeek 间的真实切换。国内可达路径需实际验证；供应商可达性不能由客户端保证。模型能力按所选 API 地址和模型单独声明：工具调用与流式输出可由用户启用或关闭，不从“OpenAI 兼容”推断自定义端点具备这些能力；用户关闭工具调用后，模型不得收到本机工具清单。新建自定义端点默认关闭这两项，OpenAI/DeepSeek 的内置默认型号默认启用，升级旧配置时保留既有行为。Mac 回复经过 Pi：OpenMuse 的工具开关限制 Pi 可用的 OpenMuse 文件工具，回复流式行为由 Pi 管理。图片理解、语音和嵌入暂未接入，设置页必须明确显示，不得让用户误以为已支持。不能因为模型支持文字就假设可以执行相同任务。

在手机小环境执行任务不代表大模型也在手机上。用户选择模型 API 时，相关对话和工具资料会发给该供应商；首版建议不依赖强制境外登录或第三方免费额度。具体模型、费用上限和离线模型优先级待定。

**端侧运行方式补充（D34–D38）**：手机端提供独立 Agent/runtime 与工具执行层，模型可按任务自动选择本机工具，不要求用户先点名 iSH。正式状态仍以结构化 SQLite、可读 Markdown 和修订记录为准；iSH 仅处理隔离运行草稿，Swift 宿主管正式记忆、目标、结构化成果及 iOS 原生能力。普通隔离运行、iSH 出站网络和公开网页的安全范围内浏览交互均不逐次请求审批；这是用户明确选择与 OpenMinis 一致的交互。敏感 iOS 数据按类别授权；正式记忆/共享资料变更及通过 OpenMuse 原生工具进行的外部高影响操作仍确认。guest 能将它可读的当前对话挂载资料发送到互联网，也能自行提交 HTTP 请求；OpenMuse 不会为 guest 内每条联网请求弹窗或声称可硬拦截外部副作用。网页查询默认 Google；Google 不可达时自动切换到用户设置的备用引擎，并标明实际来源；未设置备用时报告无法搜索。实现已加入 Google 与 Bing/DuckDuckGo 备用选项；真机曾实际尝试 Google 后回退 Bing，当前网络下 Google 成功仍待验证。浏览器只访问公开 HTTPS，支持受限点击和非敏感字段输入；自动登录、表单提交及高影响页面操作仍不开放。工具执行详情从现有活动记录进入，不另加消息胶囊（D36）；D38 要求每次工具调用可查看工具名、稳定调用编号、执行设备、脱敏参数、返回内容/错误、状态、起止时间和耗时，并支持复制；运行中已经到达的 iSH 输出也应持续可见，最终结果不能替代过程记录。详情作为独立同步记录存储，超限内容明确截断；命令、网页和文件返回可能包含私人内容，应按私有资料保护。T57 已将 iSH 累计输出写入运行中活动记录，Core 测试和真机终态详情通过；运行中的手机详情实时刷新仍待设备 UI 验收。Mac 在线且有相应能力时优先 Pi；断开后手机 runtime 接手支持的步骤，Mac 专属步骤显示等待设备。guest 工作区按对话隔离，附件只读，不挂载正式 Agent 工作区、数据库或 Keychain；iSH 与 iOS App 共进程，不是强隔离 VM。完整 native offload、双端自动同步及后台任务续跑仍未验收；模型与 iSH 共用会话浏览状态已由 T62 真机验证。详细对照见 [端侧运行时方案](ON_DEVICE_RUNTIME.md) 和 [OpenMinis 手机运行时对照](OPENMINIS_PHONE_RUNTIME_COMPARISON_2026-10-11.md)。

**guest DNS 实现状态（T63/T67）**：已参照固定 OpenMinis 源码，改用 iOS resolver 列表写入 guest `resolv.conf`，并在网络路径变化时刷新；该实现包含在签名并安装的 iOS 0.1.0 Build 3 中。T67 真机读到 resolver `198.18.0.2`，`example.com` 解析为 `198.18.0.45`，HTTPS GET 返回 HTTP 200、退出码0。`198.18.0.0/15` 属于 IANA Benchmarking 保留段，不是全球可达地址；结果证明当前设备的 iSH guest 网络路径能够完成 HTTPS 请求，不证明真实公网 DNS 解析或无代理直连。取消/崩溃恢复与其他网络下的对照仍待验证，详见 [T67](ITERATIONS.md)。

**手机浏览器补充（D39）**：将两项一次性网页函数替换为统一 `browser_use` 动作工具。标签按对话持续存在，允许模型在同一 WKWebView 上连续 search、navigate、read、find、click、type、scroll 和管理标签；跨工具调用记录 tab ID 与实际页面结果，详情仍从活动记录进入。搜索动作固定 Google 优先，仅在不可读时尝试用户预设备用引擎；动态事实请求先被约束为真实 `search` 动作，不能用普通导航冒充搜索。公开 HTTPS 浏览不逐次确认；禁止任意 JavaScript、Cookie 操作、下载和明显高影响提交，并在密码及验证码输入处失败关闭。按对话保存的 URL 可能含公开搜索词，只保存在本机 `UserDefaults`，不进 iCloud/Mac 同步；重建标签会重新加载 URL，但不会恢复原页面 DOM 或 Cookie。

**当前实现补充（D40，覆盖 D39 的部分存储与工具暴露描述）**：浏览器工具默认提供给 iPhone Agent，只有用户明确要求离线或不要浏览时才隐藏；明确打开公开 HTTPS URL 会强制执行 `navigate`，失败后停止模型回合并报告真实错误。标签元数据按对话保存在本机 `UserDefaults`，WKWebView 使用系统默认持久存储；普通站点会话数据可跨 App 重启保留，但页面 DOM、滚动位置和表单运行态通过重载 URL 不会恢复。浏览器数据仍仅在本机，不进 iCloud/Mac 同步。工具操作从头像进入现有活动详情查看；详情默认全高，进度和操作记录处于同一个可滚动区域，展开后可看参数、返回结果/错误并复制。实现和真机验收见 [T58](ITERATIONS.md)。

**手机浏览器与 iSH 共用标签（D41）**：iPhone Agent 与 iSH 使用同一 `IOSPhoneBrowserRuntime` 和当前对话 ID；guest 内的 `openmuse-browser-use` 经 native offload 进入同一标签池。因此，模型用 `browser_use` 打开的页面可以由后续 iSH 命令通过 `list_tabs`、`get_readable` 等安全动作继续操作。真实 iPhone 已验证同一 `tab_id=1` 的导航、列出及读取；两次 iSH 调用在活动详情保留实际命令、调用编号、执行设备、参数、结果和时间。此切片没有接入上游任意 JavaScript、Cookie、下载和页面截图回传，不能称为全量 API parity；详见 [T62](ITERATIONS.md)。

**浏览器动作对齐补充（T64）**：固定 OpenMinis 源码中的会话级标签池和浏览器动作是端侧参考。OpenMuse 保持当前对话持久标签、模型/iSH 共池、公开网页无需逐次审批和活动操作记录；现已补 `get_backbone`、`scroll_and_collect`、`hover`，并限制结构深度、采集条数、滚动次数和等待时间。它们通过模型 `browser_use` 与 iSH 的 `openmuse-browser-use` 共用。截图图像回传、任意 JavaScript、Cookie 工具和下载仍未实现，需先补齐模型多模态、下载构件归属及敏感会话数据处理；详见 [T64](ITERATIONS.md) 与 [OpenMinis 端侧对照](OPENMINIS_PHONE_RUNTIME_COMPARISON_2026-10-11.md)。

## 21. 主聊、活动标题与记忆页可读性（2026-10-12）

主聊是唯一持续对话，不因“新对话”操作被切成新的根会话；用户发起的旁聊各自独立，并能回到主聊。升级时将旧版本地根会话合并到一个主聊，消息按时间连续展示，消息附件、目标、构件、活动和任务继续关联；旧记录保留为隐藏迁移痕迹，导入的其他 AI 聊天继续独立，不混入主聊。

活动列表使用每项请求的具体标题，优先采用已建立目标的名称；普通请求使用首句形成短标题。当前状态/阶段单独作为副标题显示，不能把所有请求写成“继续聊一聊”。这是 OpenMuse 的实现规则；Muse 真机截图显示了有语义的任务名与阶段，但不能据此声称了解其内部标题生成算法。

Dreaming 设置按“回顾说明、手动回顾、自动开关、计划与预算、回顾记录”分组。时间和预算值须在 iPhone 窄屏中完整显示；自动计划关闭时折叠仅在开启后才需要的时段、时区、漏跑和预算选项；历史反思按需展开，待确认的建议仍可直接查看和处理。

“当前记忆”列表是结构化记录的管理界面，保留显示已过期或尚未生效的记录及其有效期，便于用户调整；`MEMORY.md` 自动维护区只投影当前有效记录，并提供完整、可迁移的详细视图；`USER.md` 是当前有效用户画像，`GLOBAL.md` 是当前有效主题索引。它们不是独立记忆库。编辑和纠正更新唯一结构化记录，修订历史保留来源，撤销保留历史，彻底忘记按既有删除规则处理。Dreaming 提案和导入推断须先确认，明确表达的日常事实可自动记录。实现依据与边界见 [记忆存储方案](MEMORY_STORAGE.md)。

**验收**：旧根对话迁移后只显示一个主聊且历史消息/关联记录可继续打开；旁聊保持分开、导入聊天不合并；“打开主聊”回到同一条记录；活动标题来自目标或实际请求；Dreaming 的时间和预算控件不换行破碎；记忆列表编辑后，重新打开 MEMORY.md、USER.md 与 GLOBAL.md 时只出现对应的同一份结构化数据。
