# 产品需求 v0.3

初稿：2026-10-09；更新：2026-10-10。状态：讨论稿。已确认用户需求与建议实现范围分别标注；本文不构成开工授权。

## 1. 产品承诺

陪一个人持续生活、学习和做事，越来越理解其处境，把愿望转成实际进展。用户换手机、换模型或停止使用本项目后，应能带走自己的记忆和成果。

第一位持续使用者是项目发起人。先证明每天有用，再扩展到其他用户。“终身陪伴”是数据连续性、理解持续更新与长期维护的方向，不能承诺模型永远不出错或服务永远不终止。

## 2. 一期产品定义（2026-10-10 用户补充，已确认）

一期目标是做出与 Muse 相近的完整产品：以其交互和运行机制为基准，而不是以最小聊天闭环作为一期交付。主要差异是执行位置与模型选择：Mac 已连接且具备相应能力时优先通过本机 Pi 执行；Mac 离线时参考 OpenMinis，由 iPhone 接手可执行的任务。不采用 Muse 的云端电脑。首期支持 OpenAI、DeepSeek 和自定义模型 API。

产品使命保留用户原文：Your purpose is to make the user's life better. You are not a generic chatbot; grow into a consistent, useful presence, and let this persona evolve over time.

“完全类似”转化为逐项可核验的体验和机制，见 [一期对齐清单](PHASE1_PARITY.md)。公开资料和真机观察无法证明 Muse 全部内部实现；未知项继续研究或向用户核对。开源实现采用自己的资产和代码，模型能力不同会影响具体输出。

## 4. 目标陪伴

用户说“想周末出去走走，别太累”。系统自动建立可见的追踪记录，说明自己正在留意这个目标，先提一两个最有用的问题，逐步了解出发地、时间、预算和同行需求。

**建议行为**：明确意图进入追踪；闲聊、引用他人愿望、否定句和随口假设不得自动变成用户目标。尚不明确的意图可以保留为待澄清项。自动记录目标不等于已获得发送邮件、花钱或改外部数据的授权。

目标记录包括目的、来源、当前阶段、下一小步、计划、进展证据、最近检查、下次跟进、完成条件及暂停原因。状态至少有待澄清、进行中、等待用户、等待设备、暂停、完成、放弃。

给出适合当前生活的计划，而非默认每天高强度打卡。连续未执行时，先判断计划是否不合适；用户说最近忙，则减少步骤。完成需符合用户约定的标准，不能因生成计划或发送提醒就标记完成。

**验收**：在连续多日的虚构旅行案例中，能发现目标、澄清、形成计划、根据预算、人数和偏好变化调整、保留历史；用户说先不去了后停止后续跟进；引用“朋友想出去旅行”不会创建自己的目标。

## 5. 兴趣动态

**建议首版**：一个低频、有限数量的内容列表，不做无限滚动。每条显示标题、来源、发布时间、简短推荐理由，以及继续聊、稍后看、不感兴趣和减少此类内容。

推荐理由与当前兴趣或目标有关，但不要将敏感私人细节露在锁屏。时效内容需在生成时检索或核验；模型猜测不能充当新闻。已看、不喜欢和重复内容影响之后的推荐。

从一篇文章进入讨论时保留来源和已有理解，支持变成学习问题、练习或目标步骤。内容推送与目标提醒分开开关。频率、条数和默认通知仍待讨论。

**验收**：虚构兴趣从旅行扩展到摄影后，内容选择随之变化；点开内容后无需重复提供上下文；推荐来源打不开时显示状态；没有可靠内容时允许空列表。

## 6. 记忆与理解

记忆至少分清：用户明确说过的事实、从行为推断的偏好、短期状态、经历、关系、目标，以及陪伴者自身的交流风格。推断不得伪装成用户原话。

每条持久记忆应有来源、时间、适用范围、可信状态和更新关系。短期状态到期后复核或降低权重。新事实与旧事实冲突时，展示当前事实和更新原因，保留必要历史，不静默改写原始对话。

已确认入库规则（D21）：用户明确说出的日常事实自动更新并可撤销；外部提取与模型推断先预览确认。

用户可查看“你目前怎么理解我”，纠正、添加、撤销变化、忘记和导出。遗忘需覆盖检索索引、导入派生信息和同步副本，并防止重新导入旧资料后悄悄复活；历史记录保留与彻底删除的规则待确定。

**验收**：“这次可以玩三天”改成“现在只能两天”后，后续建议采用最新状态；模型切换后保留同一身份、记忆和目标；用户纠正的内容优先于模型推断。

## 7. 点子与多源信息

点子显示“为什么现在值得考虑”、参考信息和一个小行动。可以接受、改写、稍后、不合适。未经用户选择不把每个点子都变成待办或正式目标。

连接器按用户选择的账号、文件夹、页面和时间范围读入；首版建议只读。邮件和聊天中的他人信息不自动成为用户本人记忆。外部文本仅作为资料，不能修改工具权限或系统规则。

所有导入先预览提取结果，保留来源并去重。其他 AI 生成的用户画像是候选资料，需识别推断与过期信息。用户已提供 [迁移提示词 v1](../prompts/memory-transfer.v1.md)，原样保存；入口、预览、结构化提取和撤销方案见 [迁移流程](MEMORY_TRANSFER.md)。后续修改另建版本，不替换基线。

邮箱首接QQ，Gmail后续扩展（D23）；邮箱访问范围、Notion授权范围、Obsidian访问方式、聊天导入格式尚未确定。Notion 和部分邮箱服务的中国网络可达性独立于 OpenMuse，不承诺所有第三方服务均无需代理。

## 8. 身份、对话与边界

**建议**：一个陪伴者，名字、头像和交流方式可设置；一段长期主对话，侧聊服务于具体主题。不同模型共享用户拥有的连续状态，人格可随使用迭代并告知，用户随时可编辑；执行权限独立于人格管理。

可以温暖、主动、诚实和有观点；不要通过讨好、内疚提醒或虚构自身经历来增加使用时长。重要结果要有证据。任务失败、不确定和不能访问的信息都明确说明。

## 9. 模型与本地执行

首期明确支持 OpenAI、DeepSeek 和自定义 API；至少验证 OpenAI 与 DeepSeek 间的真实切换。国内可达路径需实际验证；供应商可达性不能由客户端保证。语音、视觉、工具调用与嵌入能力分别声明。不能因为都支持文字就假设可以执行相同任务。

在手机小环境执行任务不代表大模型也在手机上。用户选择模型 API 时，相关对话和工具资料会发给该供应商；首版建议不依赖强制境外登录或第三方免费额度。具体模型、费用上限和离线模型优先级待定。

## 10. 一期完整交付与内部开发顺序

一期交付按 Muse 对齐清单验收，不能将“兴趣动态、点子以后再说”的小版本等同于一期完成。内部可以先做旅行闭环，再补齐各页面和机制，逐步安装自用；这些是中间里程碑。

五种信息入口都保留为一期需求：邮箱、Notion、Obsidian、聊天导入、手动记忆。具体账号和格式待讨论；实施可以分批，但任何未完成项必须在一期验收中列明，不能默默后置。

## 11. 长期远程桌面（用户已确认方向，实现待设计）

Muse 的“桌面端—打开浏览器”作为入口参考。OpenMuse 长期将其扩展为连接个人电脑并查看、操作远程桌面，体验参考 UU 远程。目标包括设备选择、连接状态、打开桌面、画面、触控/键鼠操作与断开；具体协议、网络穿透、是否复用已有客户端、支持哪些电脑系统尚未确定。

Pi 执行与远程桌面是不同能力：Pi 可在后台处理工具任务；远程桌面提供用户可见、可操作的电脑界面。远程桌面需要目标电脑在线，Mac 离线的手机接手不能让关机电脑继续显示桌面。自动操作桌面与用户手动操作的权限和占用协调待设计。

长期候选验收：从手机“电脑”入口连接自己的在线电脑，查看画面并完成一次输入；断线可恢复、主动断开即时生效；电脑离线时明确显示状态，不展示虚假可操作桌面。该项不作为一期已实现承诺。

## 12. 非本阶段范围与衡量

当前不实现产品代码、部署、真实账号接入或设备保活实验。未来首个版本不默认承担支付、自动发送邮件、全盘扫描、任意操作其他 iOS App 或无限制执行插件。

成功看真实目标是否推进、建议是否值得行动、重要事实是否记对、纠正是否生效、主动消息是否有用、双端状态是否连续。消息数量、在线时长和通知数量不能代替产品价值。建议用十四天自用记录作第一轮判断，阈值在方案确认时确定。

## 13. 核心文件与便携数据

SOUL.md、USER.md、GLOBAL.md、HEARTBEAT.md 是必需的可访问文件。文件职责、读取预算、结构化来源、迭代修订、同步冲突、导出迁移与遗忘见 [完整方案](MEMORY_STORAGE.md)。人格原文与界面说明分开保存；记忆不能只存于模型私有会话。该协议为候选，需与产品体验一起确认。

## 14. 真机细节转化的候选验收（2026-10-10）

基于第二轮 Muse 观察补充：动态每条可展开推荐原因及创建时间；动态指令编辑说明只影响今后内容、可取消且未改动禁用保存；身份文件有阅读和 Markdown 编辑方式，支持下载/PDF/分享入口。保存、遗忘与导出具体行为须验证，不默认复制 Muse 的翻译异常。

一期电脑执行界面需覆盖任务启动、连接、执行状态、用户介入、停止确认和退出后的结果；参考 Muse 的浏览器控制布局，长期完整个人电脑远程桌面仍属 R1。画面传输、键盘、平移缩放及“完成控制”和“停止任务”的语义须在技术关卡定义和验证，不能将本机 Pi 的文本工具调用等同于完整远程桌面。


## 15. 旅行工作流补充验收（2026-10-10）

复杂旅行任务可由主聊建议并创建主题旁聊，无需用户重复全部约束；上下文和执行状态连续。澄清问题可用少量选择卡，也接受自由文本回答。默认假设、用户确认和真实日历约束分别标明，不能把模型建议、测试草案或日历空白自动提升为用户决定/空闲事实。

成果可在聊天中呈现长表格和备选方案，支持折叠/展开及回到最新消息。是否自动形成资源库构件需要另定规则；生成行程不等于旅行完成。工具检索和价格等核实结论应有可追溯来源，不只写“核实过”。目标关联必须能在结构化目标记录中核对。

长表格的展开候选交互为独立表格查看面板，关闭回到原聊天及阅读位置；须验证长内容与横向宽表的可读性。

## 16. 本地截图的设计使用要求

交互实现前先查看 [截图使用说明](muse-research/SCREENSHOT_GUIDE.md)：从项目 `.research-local/muse-ui/2026-10-10/INDEX.md` 查找并实际打开对应页面截图，以 `MANIFEST.json` 核对路径/时间/校验值，结合交互档案判断已验证与未知行为。设计记录关联需求 ID 与截图；使用虚构数据和原创资产复现体验，原图不进入公开仓库或产品素材。

新设备 clone 不包含原件，须明确缺失并通过私人迁移或重新连接手机补看；不能仅看公开文字就宣称完成视觉对照。截图只能支持静态视觉证据，机制、动画、执行与同步另行验收。旅行目标写入、新增备选和构件两入口已在本例验证；后续优先补构件再次编辑/历史、受控记忆维护和异常路径。

## 17. 目标与备选成果补充验收（2026-10-10）

旅行可以关联已有长期目标；关联结果须在目标详情、进度和来源中可查。一次进展因重试、同步或重复处理不能重复写入时间线；不同事件则保留独立记录。Muse 本次出现相同进度两条，原因未知，作为验收反例而非要复制的交互。

用户要求“保留原方案，新增备选”时保留原方案，两版并存且可对照差异；备选不覆盖已确认约束，更不能把尚未确定的天数、日期、人数提升为事实。成果在聊天和资源库可达，生成中、成功、失败与继续修改有明确状态；只有可打开并核对内容才算交付。构件是否逐次版本化及自动保存规则仍待方案讨论。

## 18. 任务头像与执行记录（用户补充，2026-10-10）

执行中的头像姿态/动效、短文案与真实任务阶段联动；工作、等待、完成、失败、离线分别定义，不能一直播放忙碌动画而无进度。点击头像进入活动列表，包含任务标题、最新说明、状态和时间；点击条目展开步骤，支持半屏到全屏、滚动和关闭返回。主执行与子任务可分组查看，工具细节按需展开，不让日常界面充满内部日志。

任务完成时头像恢复、列表说明更新，成果可打开；界面说明不能代替真实完成证据。具体动画素材、时长、曲线及辅助功能待交互方案确认和真机验证；本次仅取得多时点截图与层级行为。详见交互档案第15节。构件须能承载交互成果（本例为网页和多版本切换），不能只支持静态文本；载体、沙箱、修改与导出方式待架构方案确认。

## 19. 2026-10-10 讨论补充

设计遵循[表达与设计原则](DESIGN_PRINCIPLES.md)。双端关系与共享资料见[DEVICE_AND_FILES](DEVICE_AND_FILES.md)：手机独立可用，连接Mac优先执行，Mac专属步骤等待；第一轮须支持外出连接家中Mac。明确事实自动记忆可撤销，外部提取/推断先确认；QQ首接、Gmail后扩展。讨论与迭代通过[索引](DISCUSSIONS.md)随时查询；完整开工条件与剩余问题见[复查](STARTUP_REVIEW.md)。

## 20. 六类缺口的补齐与阶段调整（2026-10-10）

用户确定Tailscale路线、iCloud可后接、耗电可运行后优化；首轮仍需手机独立和外出连接Mac。共享资料先经认证连接同步本地副本，不声称Mac离线时两端实时一致。构件见[ARTIFACTS](ARTIFACTS.md)，主动性/费用/遗忘见[POLICIES](POLICIES.md)，交互参照截图的具体规格见[UI_SPEC](UI_SPEC.md)，任务/验收/节奏见[IMPLEMENTATION_PLAN](IMPLEMENTATION_PLAN.md)。这些补充取代“尚未制定”的状态；实施默认值待整体审阅，未做产品验证。
