## T13：2026-10-10 Mac 与 iPhone 的首轮连接

落实双端关系时，先实现了 Mac 私有配对和 Pi 聊天代理。连接使用独立 HTTPS 8443 `/openmuse` 路由、Mac loopback 服务、短期一次性码、钥匙串凭证和设备撤销；不复用 Lody 的端口或凭证。单元/集成测试已覆盖本机配对生命周期，但当前 tailnet 路由、真实模型调用和蜂窝真机还需验证。聊天桥接不代表工作区同步或 Mac 工具执行。

尚未解决的实现边界：要让 Pi 安全读写指定 Mac 文件并打开浏览器，需要确定沙箱方案、目录授权界面、审批/取消和副作用日志。当前首轮关闭 Pi 工具是安全默认；建议下一步只开放 OpenMuse 专属任务目录中的受限文件操作，再独立验证浏览器动作，绝不暴露任意 shell。此建议待后续讨论，暂不改变一期需求。

2026-10-10 后续实现采用一个更窄、可撤销的首步：用户在 Mac 设置里主动选定单个只读文件夹；每轮 Pi 只拿到由原目录复制出的临时文本快照，原文件不写回。快照排除隐藏项、符号链接和非 UTF-8/非文本文件，限制深度、文件数与总大小；只有 `list/read` 两个自定义工具可用，不开放 Pi 内置工具、shell、浏览器或网络动作。取消会终止 Pi 子进程；本地 JSONL 只记录相对路径、工具名、时间和结果，不写入文件内容。下一步仍需把具体工具步骤与任务检查点/活动详情关联，验收真 Mac 文件夹授权与撤销；写文件审批、浏览器和桌面操作保持未实现。该实现选择是首轮安全切片，不改变一期更广泛的 Mac 执行目标。

## T14：2026-10-10 Tailscale HTTPS 的 iPhone 验收风险

当前 Mac 的 Serve HTTPS 路由从 `curl` 可用，但相同路由的 Swift `URLSession` 自连接测试失败，错误码 `-9816`；本机 loopback HTTP 正常。尚无在线iPhone测试，因此根因未定。Tailscale公开问题[#19147](https://github.com/tailscale/tailscale/issues/19147)报告过iPhone无法打开 `.ts.net` Serve HTTPS；一位贡献者在其中将一组案例归因到第三方DoH/DNS覆盖，另有后续用户报告尚无解决方案。问题记录是排查线索，不证明OpenMuse或该手机存在相同问题。

2026-10-10 排查补充：Apple 将 SecureTransport `-9816` 定义为 `errSSLClosedNoNotify`（服务端关闭会话但未发送通知），它本身不表示证书校验失败。Mac 上普通、显式绕过代理、强制解析到 tailnet IP 的 `curl` 均返回 HTTP 200 且证书校验结果为0；进程环境没有代理变量。故排除“curl 只是经普通 HTTP 代理成功”的解释，但 `URLSession` 的差异仍未定位。Apple 错误码说明见[Secure Transport Result Codes](https://developer.apple.com/documentation/security/secure-transport-result-codes)及[`errSSLClosedNoNotify`](https://developer.apple.com/documentation/security/errsslclosednonotify)。iPhone 未连接，仍不能从 Mac 测试推断手机结果。

本轮不降级为明文、不跳过证书验证、不改动Shadowrocket/VPN/DNS。等iPhone解锁并连接Tailscale后，先测MagicDNS解析与Mac的HTTPS健康地址；若失败，再按设备日志判断要不要试独立网络配置，先回退、单变量验证。备选架构另行记录和讨论，不作为当前既定实现。

## T17：2026-10-10 修复 Mac URLSession 的 Tailscale 直连

后续对比发现，`URLSessionConfiguration.connectionProxyDictionary` 显式写入 `HTTPEnable/HTTPSEnable/SOCKSEnable = 0` 时无法访问本机 Tailscale HTTPS Serve；设为空字典后，同一请求返回 HTTP 200。`MacBridgeClient` 已改为空代理字典，并由真实 `URLSession` 路由检查及全量 17 项 Core 测试确认。T14 是修复前历史记录，当前 Mac 到自身 Serve 的客户端失败已关闭；仍未解决的是 iPhone 到 Mac 的真机/蜂窝验收，不可由本机自测推断。

## T31：2026-10-11 记忆有效期与纠正规则

模型上下文长期使用会受“事实曾经正确、现在已过期”影响，因此为结构化 claim 增加可选 `validFrom`/`validUntil`，与记录状态和创建时间分开。默认采用可撤销的规则：用户明确表达的事实以原消息时间作为生效时间；只在明确偏好纠正且主题重合时，旧记录结束并保留为历史，新记录从纠正时间生效；过期记录不阻止重新记下同一内容，也不被当成当前偏好再次 supersede。其他 AI 的历史快照、外部提取和模型推断不根据文本日期自行推定时间，用户可在记忆页设置或修正生效/截止日，日期修改保留修订。

## T36：2026-10-11 会话 Agent 草稿的迁移边界

端侧工作区已经从 Caches 持久化到 Application Support，但此前换机或重装迁移会丢失仍有用的任务中间草稿。按用户已确认的本地优先、可迁移数据与不依赖付费云端的方向，采用显式归档而非把每个临时草稿自动推入共享记忆：仅在用户勾选包含聊天时，把相关会话工作区放进 ZIP/JSON 迁移包。草稿保持对话隔离、不进入同步记录和长期记忆。

导入执行逐文件路径/大小/UTF-8/摘要校验；同内容幂等跳过，遇到本机同名不同内容时保留本机原文并把外来版本放进冲突副本目录。数据库与文件系统无法一起原子提交，因此若后续草稿恢复失败，UI 明示记录已导入并可重试；重复导入会继续恢复文件。自动双端同步仍是缺口，不由本次迁移能力替代。若要回退，可停止导出/导入 Agent 草稿，不影响 SQLite 正式资料和已保存构件。

## T39：2026-10-11 居住地变化的记忆更新边界

沿用用户已确认的规则：用户直接表达的日常事实应自动更新并可撤销，模型推断与外部资料须预览确认。为避免搬家后旧居住地继续出现在当前画像，本轮采用窄范围规则：只有用户直接陈述现居地或已搬迁时，才结束旧的现居记录并保留其来源、修订及有效期；籍贯/出生地和现居地属于不同事实，互不覆盖。计划搬迁、假设、疑问和第三方信息不自动入库。此规则可回退为保留双条并人工编辑；不据此宣称通用事实冲突已解决。验证与剩余缺口见 [T46](ITERATIONS.md)。

实现补充：同一句同时明确籍贯和当前居住地时，现居子句可结束旧现居记录，籍贯记录继续保留；仅含未来或不确定搬迁计划且没有现居子句时，整句不自动写为长期事实。这个解析边界是本次实现中的保守规则，不扩大为一般复合句抽取。

## T40：2026-10-11 Dreaming 提案的原话依据

沿用已确认的边界：模型回顾只能提供待审建议，不得直接改写用户记忆或人格。依据 Muse 研究档案中“建议应有理由和证据”这一产品方向，OpenMuse 的新建议采用结构化原话证据：每个来源 ID 必须对应用户消息中逐字存在的片段；界面同时给出片段和完整来源；用户采纳时再次验证原句未变化。缺失、伪造、错配、助手内容或过期来源不会写入记忆。

引文存在不等于模型归纳必然正确，也不能校准模型的把握度；所以保留逐条用户确认，并把界面百分比标为模型自评。该改动不声称 Muse 私有实现也是逐字引文协议。旧提案的 evidence 字段可缺省并继续解码；新提案在确认前仍须有来源内容。验证见 [T47](ITERATIONS.md)。

## T41：2026-10-11 对现有明确记忆的审阅式更新

一般事实冲突仍不能安全地靠关键词或规则自动判定。为减少画像里“旧偏好仍有效”的情况，Dreaming 可以对近期用户原话与一条相关、有效、非敏感、user scope 且非推断的现有记忆提出一对一更新建议；提示中只包含本轮实际匹配到的记忆，解析器也只允许引用这同一集合。身份页并列展示旧记忆、新表述、逐字原话和完整来源，须由用户确认后才结束旧 claim 的有效期并写入新 claim；旧 claim、修订和来源继续保留。

这是模型归纳的审阅路径，不把用户已确认的“明确日常事实自动更新并可撤销”改写成一律需确认：已经有明确句式识别的纠正仍沿用原路径；该新增路径只补规则暂时无法识别、需模型比较的窄场景，并将新措辞标为推断。拒绝不改任何 claim；提案期间旧 claim 变化会标记过期。新提案还保存每条来源用户消息的全文摘要；即使引用句仍保留，只要原消息正文被编辑，提案也会过期，不覆盖新状态。仍不解决通用语义冲突、主体/时间抽取与完全自动化冲突裁决；若模型检索没命中旧记忆，也不会提出更新。回归结果见 [T50](ITERATIONS.md)。

用户测试上海天气时看到百度结果，希望改用 Google；并要求无 Mac 时的手机交互和本地运行环境参考 OpenMinis，让 iPhone 可处理更广泛任务。用户先要求比较实现再讨论改法，后续明确选择风险分层权限，并选择 Google 不可达时自动切到自己设置的备用引擎。此记录确认的是目标与策略，不代表相关代码已修改。

## T88：2026-10-15 结构化参考资料不得成为模型的第二条用户消息

用户报告：在新安装包中正常聊天后，模型直接输出 `<openmuse-reference-data>`、USER.md 说明和自动维护标记。复核实现确认，参考资料曾以单独 `role=user` 轮次注入，随后当前问题又作为另一条用户轮次；系统提示也把这些资料描述成 user messages。这会让模型误把私有资料包装当作需要回应的输入。

采用方案：把资料和本轮原话合并在同一用户消息并使用显式边界；系统提示只要求回应当前消息，禁止复述边界内的内部资料；增加流式输出与保存前的标记泄漏保护，命中时清除本轮内容并报告拦截。工具意图继续从当前消息正文判断。该方案修正消息角色语义并提供防御层，不更改结构化记忆真值、Markdown 投影或自动记忆维护规则。

自动化测试全量通过并已安装 Release `0.1.4 (16)` 到 iPhone 16 Pro。没有真实模型重放、PUA 视觉验收或跨模型测试；具体范围和证据见 [T88](ITERATIONS.md#t88)。
