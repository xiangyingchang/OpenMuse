# 表达与设计原则

2026-10-10用户明确指定：表达、设计遵循《Don't Make Me Think》与《写给大家看的设计书》，视觉和交互风格参考Muse。本文件将原则应用于OpenMuse，不是两本书全文摘要；本轮核对作者/出版方公开目录与说明，没有阅读完整书籍。

## 用户一眼能理解

页面让用户知道在哪里、能做什么、目前发生了什么。使用熟悉的入口和动词，点击目标外观明确；主要操作突出，帮助放在需要它的位置。文案先说结果和下一步，删去客套、内部术语和重复说明；按扫描阅读组织标题、短段落与标签。配置模型、连接电脑的必要技术信息在对应设置中解释，日常聊天不展示工具命名空间。

例如“等待电脑连接，已保留进度”，比“Runtime unavailable”更清楚。空态给一个可开始的动作，不要求先填写长画像。首聊用旅行打开话题，允许不确定日期与偏好，不把陪伴变成问卷或进度考核。

## 对比、重复、对齐、亲密性

- 对比：主次操作、标题与正文、正常与失败状态清楚；状态不只用颜色表示。
- 重复：导航、按钮、卡片、图标语义、文字层级和间距沿用统一规则；相同操作在不同页面保持同义。
- 对齐：文字与控件有明确对齐线，长消息、表格、键盘和双端布局保留可读秩序。
- 亲密性：有关内容靠近，例如任务状态、说明、时间与成果；无关内容用间距分开。

## Muse参考与OpenMuse验收

保留Muse的陪伴感、头像状态、五个主要入口、主题旁聊、活动逐层展开与成果卡体验。先按SCREENSHOT_GUIDE实际打开对应本地图，再制定原创组件和资产。原版不清楚的译名、重复记录和宽表截断不能成为复制目标。

每个关键任务用简单操作验证：用户能找到下一步，知道任务是否在执行，知道需要自己做什么，能返回并继续。检查大字号、VoiceOver标签、减少动态效果、浅/深色、键盘和长表。用户遇到困惑就记录、调整并再验证；不只用“好看”作为通过标准。
