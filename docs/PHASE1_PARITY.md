日期：2026-10-11。用户已确认产品范围并以 D31 授权实现。此表区分确认范围、建议验收细节与当前测试证据；逐条完整状态见[需求覆盖审计](REQUIREMENT_AUDIT_2026-10-10.md)。2026-10-11 iPhone 真机 DeepSeek 与旅行计划闭环、手机本机只读网页搜索、Tailscale App 配对和首次工作区事件同步已通过；本机 MacBridge/Pi RPC 合成端到端已通过，18项版本冲突仍待选择，蜂窝连接及 iPhone 真机 Pi 接管未通过。用户已将远程桌面 R1 明确排入二期，不纳入一期验收。

## “相同”如何判断

对齐信息结构、入口、关键路径、状态、反馈与长期主动工作；使用原创代码与产品资产。每项给出正常、空、加载、错误和离线状态。供应商、连接器和系统限制导致能力差异时标明，并讨论是否接受；不能静默把该项从一期删除。商业订阅、Meta 账号体系、Muse 专属渠道与其全部连接器目录不默认照搬，具体同等体验范围待确认。

用户另明确要求尽可能像素级还原。每页需在同一设备/视口保存 OpenMuse 截图，与私人 Muse 参考图叠加或做差异检查，记录页面、状态、版本和偏差；品牌素材和代码保持原创。

建议按十四天连续自用核对有用程度，再给一期验收结论。没有真实运行证据，UI 相似不能替代后台机制通过。

## 二期需求 R1：远程个人电脑（不计入一期验收）

用户新增并已确认：Muse 的“电脑—打开浏览器”长期转为打开连接个人电脑的远程桌面，参考 UU 远程。用户于 2026-10-11 明确将它后置到二期，优先完成一期其他需求。保留设备选择、在线/离线、连接、查看、输入、重连和断开路径；目标电脑在线是前提。此项独立于一期 Pi 与手机接管，不阻塞一期验收。

待讨论：支持 macOS 还是同时支持 Windows；复用现有远程服务还是自建协议；局域网与外网连接；用户主动操作和 agent 操作是否共用桌面。现阶段不指定 UU API 或声称其可集成。

每次补充记录日期、原意、需求 ID、阶段、待讨论点与验收；需求改变时保留旧结论及撤回原因。PRD 是需求入口，DECISIONS 是确认记录，本文件负责逐项验收。未知 Muse 行为可在对应迭代请用户重新连接观察；不凭记忆补造行为。
