# 构件协议与运行方案 v1

2026-10-10。以下为制定的实现基线；Muse旅游网页仅提供交互启发，不直接复用其网页与素材。

## 数据与版本

Artifact：artifactId、kind(document/web)、title、conversationId、goalIds、currentRevisionId、status、createdAt。Revision：revisionId、parentIds、sourceMessageIds、assumptions、files(hash/size/type)、dataSchemaVersion、previewRef、createdByAttemptId。manifest与UTF-8内容/JSON数据、附件形成可迁移包；路径只允许相对路径，拒绝越界/符号链接逃逸。

状态：draft → generating → validating → ready；失败为failed，原ready版本仍可打开。用户明确要成果、接受点子并产生成果或已有构件修改时进入资源库；普通短回答不自动堆构件。聊天卡与资源库引用同一artifactId，生成中有占位和最新说明，ready才可宣称交付。

“保留七天，新增五天”在同一构件的数据中形成两个命名方案，改变天数不是覆写原版本。每次成功修改新建不可变修订；只在校验通过后切currentRevision。历史可预览、恢复（新增恢复修订，不改旧版本）。同基线并发修改先保留两分支，用户选择/合并；审批和旅行事实不随方案自动成立。

## 显示与权限

原生正文渲染 Markdown。网页构件在 iOS/Mac 的非持久 WKWebView 中载入 HTML，不注册原生消息桥；加载时在内容前插入 CSP，允许内联脚本/样式和 `data:`/`blob:` 图片、媒体，拒绝网络连接、表单、嵌套 frame、对象和 base URL。宿主导航代理拦截离开当前页面的跳转。HTTP(S) 外链会显示原生确认，只有用户点“打开”才交给系统浏览器；取消后页面留在当前视图。外部脚本、跟踪图和其他 URL scheme 不会获准。Web 构件可从文件选择器加入 PNG/JPEG/GIF/WebP/HEIC 图片；正文中的 `openmuse-asset://{id}` 会在加载前由应用替换为经过校验的 data URL。单图上限 5 MB、每构件最多 32 张/20 MB。字体、音频/视频独立资源协议仍未实现，也没有对系统 WebKit 的全部攻击面做渗透测试。

Web 内容无宿主工具桥。需要修改/检索时用户回到关联聊天提出请求，由 agent 生成下一修订；不在网页里直接调用邮箱、Pi 或供应商密钥。HTTP(S) 外链确认路径已实现，UI 测试检查网址主机名、取消和页面状态保留。图片素材独立保存并校验 SHA-256，HTML 用本地资产 ID 引用，预览时转为内嵌 data URL；网页不会请求第三方跟踪资源。其他未导入的本地资源无法读取。

交互状态（切换标签等）默认页面内临时保存；表单若需持久化，只能走后续专门的带schema数据通道，首轮不开放。这是明确一期边界，不伪装所有Muse任意Web应用均已支持。

## 导出与验收

导出 Markdown/JSON 用于结构资料，网页以含 manifest/本地资产的 ZIP 迁移；PDF 为阅读快照（无交互），分享由用户发起。文本构件菜单可单独导出 Markdown、JSON、PDF 阅读版和 ZIP 构件包。ZIP 包含 manifest、artifact JSON、revision JSONL、HTML/Markdown 正文及全部被当前/历史版本引用的图片；资源库导入时校验每个文件并恢复图片。每个素材有 SHA-256，拒绝越界路径，导入遇到 ID 冲突会另存副本，不覆盖已有构件；缺少原对话时会建立新对话容器并移除不能回链的来源消息 ID。图片资产使用认证桥接通道在已配对设备间按摘要上传/下载，并随构件删除墓碑清理。网页 ZIP/PDF 单件导出不代表网页已缓存到共享工作区。工作区导出另使用 ZIP 容器，内含 manifest、JSONL 结构记录、聊天附件，以及按 `artifact-assets/{artifactId}/{assetId}.bin` 保存的全部构件图片。构件图片不依赖是否包含聊天；导入会按构件版本引用校验媒体类型、大小与 SHA-256，素材路径限定为安全 ID。凭证不在包里。资源库和构件预览菜单可永久删除构件；SQLite 事务删除当前内容、全部修订和冲突，追加不含正文的同步墓碑，旧迁移包中的内容、修订和冲突均不能复活。

## 聊天附件

2026-10-10 首个可用切片支持用户从文件选择器添加 TXT、Markdown 和 PDF，每条消息最多 5 个、单个最多 10 MiB、合计最多 20 MiB。文件以不透明 ID 保存在本机工作区附件目录；SQLite 记录保存消息/会话关联、类型、大小与 SHA-256，读取前核验校验值。可提取的 UTF-8 正文或 PDF 文本最多 20 KB 会作为本轮模型上下文，并按不可信来源处理。PDF 没有文字层的页面会在本机用 Vision OCR，单份最多处理 20 个无文字页面；超过上限会在模型上下文中标明，提取结果仍作为不可信附件资料。OCR 在发送阶段异步运行，不阻塞主线程；Vision 无法识别时保留原件并如实传空文本。消息保留附件卡，可通过系统分享入口取回原文件。已配对的 iPhone 发起工作区同步时会用认证 HTTPS 上传/下载附件原件，Mac 只允许传输当前工作区登记的附件 ID，并校验长度和 SHA-256；缺少另一端原件时可补齐，摘要冲突时拒绝覆盖。

工作区迁移 ZIP 可选择是否包含聊天：聊天附件元数据与原件仅在包含聊天时导出，不含聊天时会列出省略并剥除消息引用；构件图片始终随其构件记录和修订导出。删除聊天附件会删除本机原件、清除当前消息引用并同步无正文删除标记；其他设备收到标记后清理副本。构件图片通过独立构件 ZIP、整份工作区 ZIP 迁移和认证桥接同步；整份工作区包可在不包含聊天时保留构件图片。构件永久删除会清理当前设备和已同步设备上的图片目录。图片消息、音频、视频和把图片作为视觉模型输入仍未接入；扫描版 PDF 的本机 OCR 已接入，真机识别耗时与中文扫描件效果仍待设备验收。

## 2026-10-10 旅行构件验证切片

自动生成旅行构件现在要求回复中至少出现两个不同的分日标题，普通聊天里提到“第一天”不会误触发。“第1天”和“Day 1”按同一天处理。若目标文字含明确行程天数，构件会记录计划天数和已覆盖天数；未覆盖全程仍保存为草稿，并且不把目标步骤标成完成。构件保留生成本轮的用户/助手消息 ID，并抽取“假设/暂定/待确认”等明确标注。此验证只检查结构，不核实旅行事实、价格、日期、天气或预订；内容仍需要用户确认。文本/网页 ZIP 与网页交互通过 Core/iOS UI 测试；图片素材保存、显示、双端认证传输、ZIP 往返和删除通过 Core 测试。真实 iPhone、多端 Tailscale 和外部旅行事实仍未验。

资源库条目摘要会显示版本与覆盖进度；构件预览页会显示已覆盖/计划天数、来源消息数量和待确认假设，让未完整草稿的状态在打开后持续可见。iOS 模拟器 UI 自动化已从资源库打开合成旅行构件并断言覆盖天数、来源数与两条假设可见。真实 iPhone 和 Muse 原图叠加差异仍未验收。

## 2026-10-11 旅行方案备选

`ArtifactRecord` 可携带命名的旅行方案列表及当前方案 ID；每个方案独立保存正文、来源消息、假设、计划/覆盖天数与更新时间。旧构件没有这些字段时仍可读取；用户第一次要求保留旧方案并新增备选时，旧正文会迁入第一个方案。明确的“保留/新增/备选/对比”等表达会创建或选择独立方案；普通修改只更新当前方案。新方案仍遵循分日结构校验；回复无效时不写入构件，因此上一可用方案与版本保持不变。若目标为 N 天，完成判断要求第 1 至第 N 天各自都有标题；只统计不同标题数会漏掉缺失日，不能完成目标。较短备选不会把更长的主目标步骤标记为完成。

预览页可切换方案，显示当前计划覆盖度、待确认假设与方案天数差异；资源卡显示方案数量。每次成功内容修改仍增加构件修订，恢复历史时连同方案集合恢复为新修订。构件包随 artifact JSON 携带全部方案，并检查方案数量、正文上限、唯一 ID 与当前方案引用；工作区 SQLite、同步事件与 JSONL 归档使用同一可选字段。

本轮 Core 用例覆盖七天草案、保留旧案并新增五天方案、后续只改五天正文、失败回复保留已有两案、旧格式构件首次扩展、方案包导入导出、缺字段兼容，以及把包含两种方案的同一构件同步到另一端；iOS 模拟器通过方案切换与覆盖天数变化 UI 测试。仍未完成外部旅行事实核验、本地字体资源、Mac 离线构件缓存/新设备恢复验收、真实同步冲突的方案选择、复杂方案差异说明与真实 iPhone 验收。恶意脚本隔离、取消/遗忘期间迟到结果的通用抑制仍按上文范围继续验收。
