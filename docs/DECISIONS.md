## 2026-10-11 持久浏览器标签与通用动作（D39）

固定 OpenMinis 提交将 `browser_use` 定义为通用工具，经 session 级 `BrowserTabPool` 调度到对应 WKWebView；同一会话可以多次调用并保留页面状态，标签 URL 会保存并在标签重建后惰性恢复。其工具包含导航、页面读取、查找、点击、输入、滚动、DOM 稳定等待和标签管理等动作，导航等待有超时且同一标签串行。OpenMuse 采用相同的运行模型，但只实现当前可安全验证的常用动作：`search`、`navigate`、`get_readable`、`get_text`、`get_page_info`、`find_elements`、`click`、`type`、`scroll`、`wait_for_dom_stable`、`new_tab`、`close_tab`、`list_tabs`。每次调用仍只带当前工具真实执行产生的参数、输出/错误和时间，展示在 D36/D38 已确定的活动详情中，不新增聊天胶囊。顶层仍只允许公开 HTTPS；每个对话最多 3 个标签、进程最多 8 个活动 WKWebView，空闲标签 15 分钟后释放 WebView，URL 元数据按会话保留并在再次使用时加载。标签正文和 Cookie 不跨 App 重启保留，也不跨设备同步。

低打断原则与 OpenMinis 一致：浏览公开页面不逐次弹窗；OpenMuse 按 D34 保留高影响操作确认，阻止可识别的表单提交、付款/购买/发送/预订/删除按钮和密码/一次性码字段，不提供 Cookie 读取/写入或任意 JavaScript。页面中普通链接仍可能触发站点定义的 GET 副作用，模型提示不能作为完全的网络隔离保证；活动详情用于事后核对实际动作。仍未实现的上游动作（截图图像回传、任意 JS、文件下载、Cookie 工具、视口/UA 控制和无限列表采集）须逐项研究，不得描述为完整 parity；与 iSH 共用页面池已由 D41 补齐。实施与真机验证见 [T58](ITERATIONS.md)。

调用详情作为独立结构化记录存储，避免塞入活动摘要后超出同步记录大小；通过现有同步和归档链路在用户设备间迁移。保存前屏蔽常见 API key、Bearer、密码、token 等凭证，并限制单次参数、返回内容和错误的大小；因此超大结果会被截断，敏感值不会原样保留。命令、网页和文件结果可能含私人内容，应按私有工作区数据对待，不放进公开日志或测试夹具。实现证据与未覆盖类型见 T49 / ITERATIONS。

## 2026-10-11 浏览器默认可用与系统持久标签（D40）

用户要求浏览器标签由模型持续操作，并要求类似问题按 OpenMinis 源码实现，不靠猜测。固定上游提交 `b4c0661d5631ebab4d1a2e6f3fd4c805d4030a6c` 将通用 `browser_use` 工具默认加入 Agent 工具清单，仅在用户关闭浏览器工具时移除；BrowserTabPool 使用固定手机视口、系统默认持久 WKWebView 数据存储、保存标签 URL 并在需要时恢复。OpenMuse 默认向手机模型提供通用浏览器工具，仅在用户明确要求离线/不浏览时隐藏；明确的公开 URL 导航请求强制执行 `navigate`，成功后模型可在同一对话标签继续读取和操作。必需浏览动作失败时返回真实错误，不让模型把自然语言补成成功结果。

标签 URL 元数据仍按会话保存在本机 UserDefaults，网页站点数据使用 WKWebsiteDataStore 默认存储，因此一般站点会话数据（例如 Cookie/localStorage）在本机跨 App 重启保留；页面 DOM、滚动位置和表单运行态通过重新加载 URL 恢复不了。站点数据和 URL 都不通过 OpenMuse 的 iCloud/Mac 同步通道传递。保留 OpenMuse 自身范围：仅公开 HTTPS 顶层页面、不提供 Cookie/任意 JavaScript/下载，不自动登录，不逐次审批公开浏览，识别到高影响网页操作时失败关闭。页面浏览动作继续使用 D38 活动详情记录。此决定 supersedes D39 中“Cookie 不跨 App 重启保留”的实现状态描述；历史决策不删除。讨论及证据见 [T61](DISCUSSIONS.md) 与 [T58](ITERATIONS.md)。

## 2026-10-11 iSH 与模型共用持久浏览器（D41）

OpenMinis 固定提交通过 `BrowserUseOffloadBridge` 让 iSH 的 `minis-browser-use` 与 Agent `browser_use` 进入同一会话级 `BrowserTabPool`。OpenMuse 现由 iPhone Agent 和 iSH 共用同一个 `IOSPhoneBrowserRuntime` 实例；每轮 iSH 调用收到当前对话 ID，经 guest 命令 `openmuse-browser-use` 的 native offload 桥回到这个运行时。因此模型打开的页面可由后续 iSH 命令列出并读取，同一个 `tab_id` 指向同一 WKWebView 标签。

此设计保持 D34/D37 的权限选择与 OpenMuse 自身的网页边界：iSH 联网无需逐条审批；浏览器只操作公开 HTTPS 页面，不开放任意 JavaScript、Cookie 工具或下载，且继续限制密码和可识别的高影响页面操作。记录仍进入 D38 活动详情。2026-10-11 iPhone 实测：模型导航到 `https://example.com/` 得到 `tab_id=1`，随后 iSH `openmuse-browser-use list_tabs` 返回相同标签，再执行 `get_readable --tab-id 1` 读回标题、网址和页面正文；两条操作详情均显示命令、调用编号、iPhone 执行设备、参数、退出码和输出。见 [T62](ITERATIONS.md) 与更新后的 [OpenMinis 对照](OPENMINIS_PHONE_RUNTIME_COMPARISON_2026-10-11.md)。

## 2026-10-11 常用浏览器动作按 OpenMinis 源码对齐（D42）

用户再次要求模型操作持久浏览器标签，并要求类似问题先对照 OpenMinis 再实现。持久标签、默认浏览器工具、跨 App 重启 URL 恢复、系统持久站点存储、模型/iSH 共池及活动操作日志已由 D40/D41 落地并经过真机验证；后续应避免重复造另一套标签状态。本轮新增 `get_backbone`、`scroll_and_collect`、`hover`，模型与 iSH 调用同一动作 schema/执行器，并受有界输出与耗时限制。无需逐次审批的公开网页访问规则不变。

## 2026-10-12 主聊连续性（D43）

主聊是一条持续存在的对话；“打开主聊”回到同一会话，不创建新根会话。只有旁聊创建独立会话，导入的其他 AI 聊天继续与主聊分开。升级旧数据时，旧根会话的消息按时间并入主聊，附件关联、目标、构件、活动和任务执行一并迁移；旧会话行作为隐藏迁移痕迹保留，已同步到旧会话 ID 的迟到记录下次加载时继续归并。活动标题描述具体目标或请求，当前阶段独立显示。身份页的活跃记忆列表保留过期/未生效项供查看和调整；`MEMORY.md`、`USER.md`、`GLOBAL.md` 的自动维护区只投影当前有效 claim，三者与列表共用结构化 SQLite 真值，不建立第二套独立记忆库。

## 2026-10-13 空旁聊、我的入口与灵动岛运行状态（D49）

iOS 主聊天顶部不再显示 OpenMuse 头像/名称入口。底部导航新增最右侧“我的”，使用系统 person.crop.circle 图标，打开原有陪伴者页面与活动/身份入口；Mac 布局不受此 iOS 导航调整影响。

iOS 运行任务可请求系统 Live Activity，并在锁屏和 Dynamic Island 显示 OpenMuse 名称、真实任务阶段与不确定进度的旋转状态。内容不包含提示词、对话标题、网址或工具参数。阶段来自本机任务/工具状态；过期后显示进度未更新，任务完成、失败或取消后短暂展示终态并收起。该能力依赖 iOS 17+ 与用户/系统允许 Live Activities；禁用或请求失败时，应用内活动记录仍为唯一状态入口。Live Activity 仅呈现运行状态，不承诺后台续跑、准时唤醒或 APNs 远程更新。官方 API 依据：[Apple Live Activities](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities?changes=_6)、[ActivityConfiguration](https://developer.apple.com/documentation/widgetkit/activityconfiguration)、[DynamicIsland](https://developer.apple.com/documentation/widgetkit/dynamicisland)。详细实现和验收见 T85。

## 2026-10-15 目标删除、兴趣动态与首屏修正（D52–D54）

Agent 删除能力由当前用户的明确请求门控，执行时还需用本轮消息重新校验；目标列表工具返回稳定 ID、来源性质与置信度。重复目标只有在来源差异足以支持唯一选择时才自动处理；否则模型先询问。删除事务清理目标、关联提醒、进展事件、目标建议与维护提案，保存删除墓碑以抑制旧同步副本；保留聊天及终态任务历史。关联任务仍在执行或等待时拒绝删除。目标页另有原生破坏性确认入口。

动态从内容发现开始：iPhone 每次打开动态页时，若距上次检索至少六小时则自动通过持久浏览器搜索；用户也可手动刷新。查询不发送聊天记录，只从有效非敏感的已确认兴趣、进行中目标标题和编辑后的动态说明生成有限查询词。搜索结果以真实 HTTPS 标题、域名、摘要及原文链接形成卡片；RSS/Atom 折叠为可选来源设置。Mac 目前只展示已同步卡片或拉取用户添加的订阅，因为 Mac app 没有 iPhone 的持久浏览器运行时。公开网页索引可能不包含登录后内容或所有帖子，不能称为 X、Reddit、小红书或微信原生连接器。官方接口范围需单独评估：[X 最近搜索](https://github.com/xdevplatform/docs/blob/main/x-api/posts/search/quickstart/recent-search.mdx)、[Reddit Devvit API](https://developers.reddit.com/docs/capabilities/server/reddit-api)、[小红书开放平台](https://openaccount.xiaohongshu.com/docs/api-reference)。

iOS 主聊右上菜单不再重复“新对话”，保留“新建旁聊”；活动页以不透明背景和大尺寸滚动区避开顶部遮挡。首次初始化才写入新的 `SOUL.md` 模板。Muse 式 About 说明单独显示在编辑器，用户原文不被存入人格文件正文；既有用户文件不自动迁移或覆盖。实现及测试状态见 [T89](ITERATIONS.md#t89)。

## 2026-10-15 模型上下文边界与回复泄漏保护（D56）

时间信息只作为系统提示中的独立索引提供，并按索引映射到传入的近期对话消息；不得把内部时间标签写进用户或助手消息正文。当前请求边界在上下文裁剪时单独保留。旁聊摘录、记忆、检索资料和附件只能作为当前请求的背景内容，不得作为额外的 `role=user` 待回复轮次。所有 OpenMuse 自有包装标签在传入前转义；流式输出与最终回复都检查内部标签，发现后撤销当前流式文本、拒绝保存模型回复，并向用户说明本轮未保存；Dreaming 的模型输出在解析和保存前使用同一检查。该拦截覆盖已知标记，不承诺识别模型对内部提示的无标记语义改写；实现证据与边界见 [T91](ITERATIONS.md#t91)。

## 2026-10-15 已知后台自述不应丢弃整条答复（D57）

继续保留 D56 对 OpenMuse 结构包装、内部元数据和记忆标记的整轮拦截。少数已实际观察到、但不包含私密内容的中文“后台事故自述”单独按完整句清除，保留该句前后的正常回答；不得把自然语言短语和结构标记混为同一类致命条件。system prompt 使用通用的“不旁白后台处理”要求，不重复具体自述原句，避免提示本身诱导模型照抄。模型原文不持久记录；运行结果只保留已过滤的用户答复和失败状态。

对照 OpenMinis 的公开发布记录，其空回复、截断回复和可继续状态分别处理，截断时保留/继续已有内容，而不是把所有情况归为一种失败；nanoMuse 将上游拒绝映射为稳定错误码和用户可读提示，并要求客户端测试映射一致。它们没有提供针对这类 OpenMuse 输出标记的相同实现，因此这里借鉴“按原因分级、尽量保留可用结果”的原则，不复用上游代码或规则。来源（2026-10-15 查阅）：[OpenMinis 1.15-beta.2 发布记录，源码提交 `b4c0661d5631ebab4d1a2e6f3fd4c805d4030a6c`](https://github.com/OpenMinis/OpenMinis/releases/tag/0-beta-build32)、[nanoMuse parity，提交 `c33c9e83804d226b689be28d4ebc8a70b798074e`](https://github.com/nano-muse/nanoMuse/blob/c33c9e83804d226b689be28d4ebc8a70b798074e/docs/parity.md)、[nanoMuse cloud error catalog，同一提交](https://github.com/nano-muse/nanoMuse/blob/c33c9e83804d226b689be28d4ebc8a70b798074e/cloud/README.md)。实现与测试见 [T93](ITERATIONS.md#t93)。
