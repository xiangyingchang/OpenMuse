# 建议落地节奏

初稿：2026-10-09；更新：2026-10-10。方案未批准，不是开工计划或交付承诺。估计以单人开发、AI 辅助、已有 Apple 开发环境为前提，不含未知审核等待。

## 先确定什么

首轮分发已确认：先装到项目发起人的 iPhone 持续自用。先讨论四个核心体验的边界、手机后台预期、复用路线、具体签名更新方式和首个连接器。确认后才安排应用实现。保留所有五类信息来源，不用“首版”把它们永久删掉。

## 建议按关卡推进

| 阶段 | 产物 | 大致投入 | 通过条件 |
|---|---|---|---|
| 0 方案讨论 | PRD、低保真交互、技术选择、验收标准 | 2–4 次讨论 | 关键决策明确并获得开工授权 |
| 1 技术可行性 | 手机小环境、Pi 适配、核心文件事务/迁移、双端/iCloud 与后台试验 | 1–2 周 | 真实设备证据、同步与恢复可行，明确后台可承诺边界 |
| 2 最小陪伴闭环 | 手机主对话、目标、记忆、手动导入；Mac 可续聊 | 2–3 周 | 旅行案例跨多日真实使用，纠正和暂停生效 |
| 3 兴趣与点子 | 有来源内容、内容续聊、建议反馈 | 1–2 周 | 推荐值得看，反馈影响之后行为 |
| 4 信息连接 | 分批接 Obsidian、邮箱、Notion | 2–4 周 | 逐个供应商授权、增量同步、去重和撤销验收 |
| 5 日常打磨 | 体验、耗电、恢复、成本与分发 | 至少 2 周自用 | 十四天连续记录证明价值，核心问题被修复 |

这些时间可以重叠，但不是简单加总的固定上线日期。粗略看是数周到数月的持续产品工作；手机后台和上游复用选择会改变估计。若技术关卡不通过，先修正承诺和方案，不靠补 UI 掩盖。

## 首个可用版本建议

iOS 与 macOS 都存在，但手机先达到独立可用；Mac 用 Pi 续聊和处理本机任务。目标和记忆是主线，兴趣动态与点子以少量高质量形式进入自用。复杂附件、通用电脑操作、多个陪伴者和插件市场后置。

不是先做一个只切换模型的聊天客户端，也不是一次建全能 agent 平台。通过同一个旅行计划案例贯穿各阶段。

## 自用反馈

每周记录值得保留的帮助、错误记忆、无用推荐、打扰、目标停滞和执行失败。优先修复导致不再愿意使用的原因，再增加能力。真实记录保存在本地；公开仓库只保存脱敏问题和合成案例。

建议验收观察：每周真实推进的目标步骤、用户主动重复解释的次数、记忆纠正成功、兴趣内容继续学习次数、点子接受或行动比例、主动通知有用比例、任务恢复与重复执行、模型费用及电量。

## 当前范围清单

- 完成：公开产品和源码调研、需求初稿、技术取舍、阶段建议、未决清单。
- 交付时核验：公开仓库建立、文档链接与远端内容一致。
- 已确认：先个人 iPhone 持续自用。
- 待讨论：后台能力承诺、签名更新、复用与许可证、具体账号类型、预算与频率。
- 明确未做：应用代码、构建、模拟器/真机试验、真实连接器接入、部署。
